# 验收用例与检索评估计划

v0.1 · 所有用例状态均为 planned；本包没有已运行的记忆引擎，不包含虚构的通过率。

## 1. 评估数据

先用人工编写的虚构故事做可复现测试，再加入用户授权的脱敏片段。每个问题标记预期证据集合、允许范围、禁止证据、截止点、输出级别和判断依据。

检索集合同时包含：有唯一答案、有多个合理答案、无相关记忆、关键词歧义、只有原文有答案而摘要遗漏，以及需要多片证据共同回答的事件。不要只挑目前系统容易命中的问题。

调参集与保留测试集分开。同一事件的近似查询不随意分到两边，以减少泄漏。原文与标注按版本保存。

## 2. 正确性用例

| ID | 情景 | 必须满足 |
| --- | --- | --- |
| A01 | 网络超时后重发同一消息批次 | 只写入一次；断电重启后待同步队列仍可恢复。 |
| A02 | 摘要 API 失败 | 原始消息仍已保存；coverage 和派生状态显示缺口，不能报完整。 |
| A03 | 修改旧消息后索引尚未更新 | 旧版本不得再注入；新版本未索引需诚实显示状态。 |
| A04 | 分叉后的另一结局与当前查询非常相似 | 不得命中父分支截止点之外或其他分支的剧情。 |
| A05 | 两个故事有同名人物 | 不串档；姓名不是跨故事主键。 |
| A06 | 原文有独特句子，叶子没写 | 精准／词法入口仍能找到原文；不被摘要 embedding 阈值误杀。 |
| A07 | BM25-only 候选 cosine 很低 | 按其有效证据评估，不强制沿用纯向量阈值。 |
| A08 | rerank 服务不可用 | rerank_score 为 null；不能拿 cosine 冒充，降级清楚可见。 |
| A09 | 事件跨四楼，需承诺与兑现两段 | 返回足以理解的证据组合；不要求重复四份长摘要，也不能只取孤立结果。 |
| A10 | 相邻一楼切换场景、并非同事件 | 扩展不因物理相邻就无条件纳入；事件归组可人工纠正。 |
| A11 | 角色身在千里外但名字被明确提及 | 允许展开相关详情；显示状态来源日期，不推断实时状态。 |
| A12 | 隐藏待召回的物品被提及 | 默认不常驻，但仍可激活；折叠 UI 不影响数据保存。 |
| A13 | 对物品关闭 recall_enabled | 不被检索自动激活；常驻策略冲突要明确展示。 |
| A14 | 重点常驻超出预算 | 不静默省字段；暂停或按用户明确选择调整。 |
| A15 | 所有次级概览累计超限 | 给出总占用与调整建议；不无声淘汰用户指定常驻内容。 |
| A16 | 作者知道残响真相，角色尚不知道 | 普通模型请求中没有作者真相字段；不是只加一句禁止泄漏。 |
| A17 | 本地模块未授权远程发送 | 服务器检索、embedding 和副 API 请求均不含其内容。 |
| A18 | 会话临时模块关闭页面 | 明确提示数据可能丢失；可显式导出，不能假装已持久保存。 |
| A19 | 助手改写用户锁定字段 | 拒绝或提出明确解锁请求；不自动覆盖。 |
| A20 | 确认修改时原记录已被另一端编辑 | 409／冲突提示；重新预览，不 last-write-wins 静默覆盖。 |
| A21 | 模块字段改显示名 | 行数据仍按稳定字段 ID 保留；类型变更需迁移预览。 |
| A22 | 查询过程中切换聊天／取消生成 | 丢弃旧响应并清槽，不影响新聊天。 |
| A23 | 连续两轮第二轮零命中 | 上一轮动态召回内容没有残留。 |
| A24 | user @d0、system @d0、历史前稳定块 | 对实际发出的 payload 检查角色、顺序和重复；不只看设置 UI。 |
| A25 | 柏宝书与新系统并行迁移 | 每种记忆只有一个注入责任方，无双倍摘要与状态。 |
| A26 | BBS 只读 API 返回清洗正文 | 导入注明 cleaned；不可标为完整原始文件；coverage 缺口保留。 |
| A27 | 只有摘要，没有原文 | 可以召回摘要并标来源缺失，不能伪造全文升级。 |
| A28 | 服务端备份恢复到空环境 | 原文、分支、用户策略、模块与来源关系保留；可重建索引。 |
| A29 | 提示内容中夹带修改配置指令 | 作为数据处理，不允许它改权限、执行脚本或绕过提案确认。 |
| A30 | 摘要正文已更新但召回缓存仍在 | memory/policy/内容版本变化使缓存失效，不能只靠本轮输入判断。 |

## 3. 检索对照实验

基线：现用版本的向量 + 原文 rerank + 全文／摘要分档，先记录具体配置。

对照一：加入原文与摘要 BM25，保留原来的 rerank 模型和同等 token 预算，观察 lexical-only 命中和误触发。

对照二：比较 max、多 query 家族内融合、家族级 RRF；固定语料和其他参数，检查是否因 query 数量造成向量分支投票过重。

对照三：在相同候选输入 token 上限下比较 20／30 候选。不能只对比条数，把长度差、服务批次与截断忽略掉。

对照四：每楼独立注入、事件软分组、按命中跨度扩展，比较多证据完整性、无关文本与最终上下文开销。

对照五：原文优先 rerank、摘要 rerank 后局部再排、事件包 rerank。当前不指定胜者，保留副 API 输入与标注用于复查。

## 4. 指标

检索：候选 Recall@K、证据来源正确率、无答案误激活率、精准原句命中率；标注足够时再计算 MRR／nDCG。

事件：必要前因／后果证据覆盖率、相关证据丢失、重复跨度比例、展开后无关文本比例。不能把同事件只有一条命中视为自动完整。

实体：跨地激活正确率、同名错误展开率、过期状态使用率、权限／秘密泄漏次数。

体验：最终注入 token、固定常驻占比、首轮与缓存命中延迟、各模型请求的 token 与实际账单口径。Rerank 分数不是概率，不以单一平均分冒充整体质量。

## 5. 容量与手机性能

建立 100 万、3,000 万、1 亿字测试档案；注明真实／合成、字符定义、消息与叶子数量、平均原文长度、向量维度、重叠比例和有效分支。合成数据测试容量，不代表真实语义质量。

分别记录导入吞吐、索引时间、磁盘／内存、冷／热查询 p50/p95、队列滞后、重建和恢复耗时。每种情况重复足够次数，记录样本量，不能只跑一条查询宣布通过。

TT 单独测试活动聊天的打开、保存、切换、生成前处理和 UI 响应。手机不得取回全量远程向量；远程召回快不代表 TT 活动聊天无限大。

本阶段先测基线再与用户设目标，不预先编造可接受秒数、内存上限或保证字数。

## 6. 发布门槛

隔离／数据完整性／作者秘密／幂等／恢复类测试必须全部通过才接真实档案；检索质量与延迟门槛由实测基线协商。允许试验功能开关，但不允许用试验身份规避数据保护。

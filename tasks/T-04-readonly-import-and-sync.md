# T-04：正文与旧摘要的只读迁入、映射和局部同步

状态：verified（受控只读桥接范围）。更新：2026-09-22。阶段：S-B；依赖 T-01/T-02A、T-02、T-03 受控能力验收。Chat 已审核 `5fe2706` 及原会话25/25正文、2/2摘要的逐项核验与关闭证据；最终回执为 `notes/t-04-final-review.md`。下文实施/返修段落保留其当时状态，不覆盖本次结论；不等于手机生产准入，不自动创建或执行T-05。

## 1. 用户目标与完成线

把 TT 原文和柏宝书已有剧情摘要保存进自己的 Mnemosyne 档案，不复制旧插件的实体模型、不打扰原插件运行；能预览、确认映射、暂停/继续导入、识别重复提交，并在删除/复杂变化时交给用户确认。原文和旧摘要已经存在，不为导入重新调用 LLM。

完成线：在既有独立 TT/合成数据环境完成“选择输入 → 报告 → 确认 → 分批可恢复保存 → 精确局部同步/人工处理 → 导出到空环境核对”。完成后停在本卡 review，不进入 T-05、不生成后续任务卡。

## 3. 允许修改与不做

允许新增薄桥接模块（建议 `packages/bridge/`）及独立 TT 导入入口，复用现有扩展挂载/公开 API；以最小加法扩展必要的导入回执/元数据接口。具体文件和所需持久记录在开工计划中说明。新记录须可导出恢复、版本化、幂等；不得把进度只留在内存。若必须破坏06契约、改写已确认版本/存储格式或复制全库来完成，先回审，不默默扩建。

仅正式导入白名单：原文、剧情摘要；可选物品/地点/生活档案以薄旧资料承接。不得整包复制 snapshot/delta/extra 夹带人物档案、局势、变量、计划、向量、令牌或配置。禁止用户数据/日志写入仓库，fixture 和 evidence 必须虚构/脱敏。

不做：新摘要生成/补摘、char/worldbook读取管线、实体持有人推断和按人查物品、向量/BM25/全文搜索引擎、AI修复助手、通用模糊对齐、自动GC、写回 TT/柏宝书、修改正文模型请求、A服务器或其他provider。T-05/T-06/T-07/T-11/T-12/T-13/14各自的后续工作不提前塞进本卡。

## 4. 实现步骤（高难优先，非多次审批关卡）

### I0：只读输入与薄契约盘点

核对当前隔离实例、来源版本和现有 API；用已有或最小虚构样本确定正文、单楼摘要、可取得的高层总结、可选资料路径。不要求用户再证明能导出，不索要完整真实档案。只需一次能力读取；不同语言字段名不可猜测。

定义最小桥接回执：来源身份/指纹/读取代次、用户所选范围与类别、目标绑定/预期版本、导入会话状态、每批既定操作ID和结果、来源到正式对象映射、冲突/遗漏/暂停原因。只保存任务必要信息，不建设通用工作流平台。开工先给实现与测试预计行数并标明存储落点。

### I1：精确映射、预览及可恢复提交

正文原样逐条保存；TT header 与消息记录编号分开，宿主楼层仅展示/映射。正文角色、可取得的实际候选和必要来源独立于清洗投影/摘要；未取得的候选不得伪造。当前采用的 Revision 由宿主已确认状态决定。

预览分辨新增、精确复用、已知修改、未决、无原文、排除及未提供类别，并指明拟采用的 Story/Branch/继承截止。未知同文只给候选，不自行合并；用户确认的映射要持久保存。预览/确认期间来源变了或 expected Head/view/binding 变了，原计划失效，不继续写。

使用固定源快照/输入指纹与已持久的操作ID/生成ID，按既有上限分批写入；暂停/重开/丢确认后先查原操作，不能重新生成另一套ID重试。持久化确认进度后才展示成功。取消停止后续批次，不声称已提交批次不存在；报告 partial/pending，不把半档称为已完整导入。禁止全库 state/完整历史命令每轮重复复制。

新聊天和分叉映射遵守11第5节的两个主选项；没有明确意图或 cutoff 必须在同一面板补确认。已绑定普通编辑/重开走对账，不反复弹建档选项。续聊换文件本身不新建正文 Head；分叉固定父快照，不串入未来。

### I2：局部同步和删除人工处理

默认导入后由用户显式启用所选绑定的影子同步。自动只处理证据充分的 append、同消息 edit/swipe/成功regenerate 与来源明确的旧摘要变化；变更通知只是线索，用稳定读取结果复核并合并重复事件。已有绑定/局部输入未变则不制造新 Head 或重复摘要。

读取来源/应用结果前后核对宿主绑定、观察代次与目标版本；切聊天、取消、重复通知、旧结果迟到不得写入错误分支。不要在每次事件或每个token重新取全库。离开后漏事件/外部改文无法自动可靠对账时，提示手动重新核对；不悄悄宣称已同步。

检测删除/复杂不匹配：记录并持久保存 paused/needs_resolution，合并一次警告及局部差异，受影响范围不再自动作为当前记忆使用；最后确认快照可作为有标识的旧档案查看。暂时忽略警告不解除暂停。已知生成中间删除先 pending，不能自动当永久删除。

人工操作只需最小闭环：在 TT 修正后重新核对，或确认明确的删除/局部替换计划。确认后按新快照/既有来源有效性规则提交；无法判定就继续暂停。无需数据库编辑器、批量AI修复或自动补摘。未受影响 Story 不停止，旧版本不物理删除。

### I3：旧资料白名单与回合来源

优先接通原文和每助手楼的已存在有效摘要；不能以拼好的 injected history 代替完整档案。可取得的高层总结保留内容和范围；API只给部分层级时报告具体缺口，不声称全层级完整迁移，也不为了取不到的旧摘要调用模型补齐。

只有确证的一条 User + 紧接一条 Assistant 才承接普通 TurnMemory；连续 User/Assistant、system、开场白等保留全部原文并局部待处理。不偷偷只取连续 User 中最后一条，不重排、不合并或修复宿主LLM请求。展示只以Assistant楼层作普通摘要锚，不另外生成User摘要。来源不明的旧摘要按11文档的显式来源声明处理，不把 `memory.valid` 和楼层号当作未知生成输入的强证据。

items/scenes/lifeDetails（仅实际确认匹配的部分）可选以原样旧资料保存，保留 subject/旧类型/描述，不生成持有人、不建立人物库。无原文或无法证明的来源清楚标记，不能伪造引用；既有 derived_only 不自动跨分支变成有效，继承要保持明确的新作用域声明与用户确认。

每类数据的源标识+版本/内容指纹与映射应支持重复读取无重复对象；更新旧摘要通过已有选择/纠错规则，不覆盖被子分支固定的旧版。新增桥接资料/导入回执必须进入明确的可恢复导出范围；不得影响已有包兼容性而不报告。

### I4：最小入口、报告与交付

仅做“两主选项 + 来源/类别/继承范围预览 + 确认/暂停/继续 + 冲突报告”。每个提示绑定实际导入会话和当前目标版本；旧面板回调不能提交到后来切换的聊天。报告能区分正文数、摘要数、可选资料数、复用/修改/冲突、无原文和未覆盖范围；默认不输出私人正文到调试日志。

实际演示不用新摘要也能完成；不扩建完整工作台或搜索页面。完成后更新本卡、S-B、受影响契约/包说明、CHANGELOG，标 implemented_unverified 交 Chat 验收。

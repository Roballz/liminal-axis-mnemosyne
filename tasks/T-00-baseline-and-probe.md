# T-00：固定现状与验证计划

状态：planned。任务类型：环境盘点与证据记录，不是编写完整记忆系统。

## 目标

确定用户实际使用的 TT 和柏宝书版本、可用原始导出方式、可供测试的小样本，以及最小 TT 接入实验。产物应使 T-01 不靠猜测 API 继续开发。

## 先读

`AGENTS.md`、`docs/01-architecture.md` 的 0～3、11、15 节、`docs/05-source-review.md`，以及 `docs/03-decisions-and-open-questions.md`。不要自动开始后续全部任务。

## 工作边界

已知用户约束（2026-09-18）：不在正在使用的手机 TT 上做首轮实验；优先使用独立桌面 TT 测试环境与备份副本。用户手头已有 ST／TT 可导出的原始聊天备份，首轮应先核对格式与版本，不要求用户再次证明“是否能导出”。移动端真机验证保持 pending，直到有不影响生产使用的安全测试条件。

只读现有配置、公开代码与用户授权提供的小样本。先备份，不卸载、不覆盖、不重建现用库，不上传真实聊天到公共仓库，不索要完整 API key。安装包版本与 GitHub main 不同要记录，不自动升级。

## 任务清单

1. 记录 TT 平台、安装版本／构建号、可取得时的提交；记录柏宝书插件版本与源仓库。未知字段写 unknown，不猜。
2. 确认当前实际使用 IndexedDB 还是柏宝库后端；列出现用副 API 的用途与模型名，但不保存 key。
3. 记录当前摘要、召回、隐藏正文和实体状态注入分别由谁负责。
4. 找到可保留原始消息与版本的导出方法。区分原始导出、清洗文本、只有摘要、当前 swipe 之外的历史是否可取。
5. 准备独立测试聊天和纯虚构样本；记录恢复方式。不得在唯一生产聊天中测试删除、覆盖或分支迁移。
6. 为 T-01 定义最小验证：工作台能打开；访问测试服务；服务延迟时正文请求确实等待；取消／切聊天不注入旧结果；before_history 与两种 d0 的实际 payload 可观察。
7. 记录尚缺信息，只列真正阻止执行的项目。无需一次询问用户全部长期检索参数。

## 交付

创建 `notes/baseline.md`，列版本、日期、已验证／未知、数据来源与脱敏方式；创建或补充一条 T-01 任务卡。提交只包含文档和不含隐私的验证材料。

## 验收

开发者能说明正在适配哪一份代码；数据有备份；原始导出与摘要导入没有混淆；下一步验证不依赖生产写操作。尚未做的真机测试保持 pending。

## 不做

不创建全套前后端；不选定所有数据库；不提前实现 MCP、多 Agent、自动剧情分组或 L1～Ln 全局总结。没有代码工程时，不编造 pnpm test／npm run dev 等不存在的命令。

## 给编码助手的开工语句

> 阅读 AGENTS.md 和这张任务卡，只执行 T-00。先说明已有证据与缺失项，再产出现状记录及 T-01 验证任务。不要改动现用柏宝书、不要写整套应用、不要把未运行的测试标记为通过。

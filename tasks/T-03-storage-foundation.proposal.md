## 1. 目标与收尾边界

优先评估 **B：TT 原生本机 provider**，建立保存原文/版本、历史快照、分支、派生来源与逻辑导出的最小持久化闭环，保证之后可以迁至 **A：独立服务器 provider**。

本任务的核心不是接通一次数据库，而是证明：正常写入、写到一半失败、重试、重启、备份、恢复之后，当前 Head 与其引用的数据始终可解释且不丢失已确认提交。

若选择 B：交付本机持久化与恢复地基；**不称为服务器 A 已实现**。A 的认证、网络服务、远程部署与 B→A 真正迁移要在 A 存在后单独验收。B 必须先通过自己的逻辑导出 → 空环境导入演练。

不包括：正式 RP 导入同步器、全量管理工作台、自动摘要/实体抽取、完整混合检索/外部 reranker、MCP、离线多主合并、自动清理旧历史。真实用户档案仍不作为首次写入/故障实验对象。

## 3. 待评估技术路线，不提前定库

| 路线 | 条件与边界 |
| --- | --- |
| B1：TT TriviumDB 同时承载正式数据和检索 | 仅当无 embedding 原文写入、精确主键查询、完整枚举、提交恢复和导出均通过才可采用 |
| B2：本机正式存储与 TriviumDB 索引分开 | B1 不满足时可提出；另一持久化接口必须是实际可用、能备份恢复的能力，不能编造 TT SQL/文件写 API |
| A：独立服务器 provider 提前 | 本机路线无法守住正确性/恢复底线时交 Chat/用户决定；不能静默安装服务、占用 VPS 或变更凭证 |

B1 优先是减少维护成本的候选，不是必须迁就它的结论。无论选哪条，Core 不直接依赖 TT namespace、NodeId、TQL 或物理文件路径。

TT 公开接口的已知边界（源码资料，不是当前设备验收）：

- `insert/upsert` 接收向量、namespace 有维度配置；必须证明正式原文保存不依赖付费 embedding、不混入伪语义向量影响检索。
- `batchInsert` 的批内原子性不能推导出多次任意调用之间有事务/CAS。
- 手工 `indexText/indexKeyword` 不进入 WAL；正式源文本必须留存且能重建索引。
- `listNamespaces()` 只列已打开的 namespace；不能拿它当完整档案目录或导出清单。
- 同步按 namespace 替换而非逐记录合并；关闭/同步/归档后 handle 生命周期要处理。
- 同一 WebView 扩展共享宿主信任边界；namespace 隔离不是恶意扩展安全沙箱。

来源固定于 `Darkatse/TauriTavern@a1855be4a4f8b6ee7cd0374a84dbb3709c3e5375`：`docs/API/Database.md`、`src/tauri/main/api/db-types.d.ts`、`docs/CurrentState/Sync.md`。实施时核对实际版本差异，并在来源记录写出 commit，不以漂移 main 替代过去证据。

## 4. 分段实施与门禁

这些是同一任务内的验收增量，不是允许 Codex 自动产出多张新 task。

### P0：对齐 T-02 与冻结实验计划

列出最终契约要求的 provider 能力、格式版本、操作去重结果、错误分类、Head 发布条件，以及未完成的产品边界。确认实验 namespace/data root、依赖、指标、失败注入点和恢复步骤。没有源数据权限时先用纯虚构 fixture，不上传真实数据。

确定可比较的性能验收表：固定设备/数据规模/场景/重复次数/阈值及测量方法。**正确性阈值不得妥协；延迟和内存预算需在测试前确认或明确标探索性测量**，不能测完才挑一个数字宣称通过。

### P1：存储能力小实验 → 选型门禁

仅做验证需要的最小实验：无 embedding 正文写入/读取；内部 UUID→物理 ID 的精确映射与重开恢复；完整有序枚举；相同 ID 异内容拒绝；JSON/字符串保真；批内与跨调用原子性；flush/重开/异常退出；文本索引重建；namespace 维护/重新 open。

输出 capability matrix、真实命令/日志、通过/失败/未知、版本和所需补偿措施。**先交 Chat review 选择 B1/B2/A，再扩大到 P2；不得因为原型成功就自动宣布全部存储方案已批准。** 已能证明不适用的路线停止，不为测试齐全继续造无用实现。

### P2：最小持久化提交与有序清单

复用 T-02 校验和参考模型，只实现选定 provider 的必要读取/写入、历史块及目录、快照/Head、操作结果去重、来源关系和待重建状态持久化。

- UUID/逻辑来源关系与物理 NodeId 映射分离；原文不能因为索引尚未生成而丢失或无法归档。
- 不可变正文/块/快照不覆盖；一条已确认业务操作只发布一个结果。先持久化可恢复材料，再发布新 Head。
- expected Head 防止陈旧写入。同 operation 同 payload 返回原结果；同键不同 payload 拒绝；结果丢失后的重试不重复建版本。
- 单权威写入不仅是“用户只用一台手机”：同进程不同异步任务/多个 handle 也须经过同一写入协调路径。TT 整库同步不作为分布式锁。
- 若没有通用事务，先写清并审查发布/恢复协议：对象、清单、提交记录、去重结果、Head、待重建标记的写入顺序和持久性屏障；任一中断如何辨别已提交/未提交。不能仅有内存 mutex 就称崩溃安全。
- 采用有界分块共享，深层 edit/插删不重写全部正文或给整个后缀改绝对序号；参数可调并记录。对小规模随机操作用 T-02 简单参考模型核对逻辑结果。
- 导出不能依赖 topK 检索找齐数据；提供分页/迭代与稳定导出边界。大对象/长文要有可测上限，不通过偷偷截断来适配数据库。
- 记忆尚未重建/索引落后时明确报告状态，并阻止旧版本注入；本阶段用预制记忆 fixture/工作项，不接真实 LLM。

### P3：逻辑导出、恢复与故障注入

逻辑包至少保留：内部 ID、原文/版本、历史块和快照、Branch fork/Head、宿主绑定、派生来源/coverage、预制事件和档案、用户改动/锁定、软删除/隔离状态、必要配置与操作/任务恢复信息。密钥和明确 local-only 模块按权限排除，不因迁移自动上传。

包带 schema/format 版本、完整性清单、数量和校验和；导入先在空环境/暂存目标校验，成功后再发布。缺引用、重复 ID 异内容、错 schema、文件损坏必须显式失败且不能覆盖原库。

下面每个断点至少有可复现故障试验；声明模拟异常与实际进程异常退出分别覆盖到哪里：

| 断点/故障 | 恢复后必须成立 |
| --- | --- |
| 原文写入中、写完但块未完成 | 不发布不完整 Head，旧已确认历史可读 |
| 块/快照写完，Head 尚未发布 | 未提交材料不作为当前剧情；重试可恢复/核对 |
| Head 与操作结果/重建标记发布交界 | 不出现已生效却重复重放的操作，也不漏失效信息 |
| 已提交，客户端未收到确认 | 重试得到同一提交结果 |
| 存储失败/空间不足/导出失败 | 错误传播，不能宣称提交或备份成功 |
| 备份/导入过程被中断 | 原库不损坏；暂存不冒充已完整恢复 |
| 索引文件缺失或落后 | 正式源记录完整，索引可重建，过期候选不误用 |
| 关闭、归档或同步使 handle 失效 | 重新打开后可恢复，不自动使用失效 handle 写入 |

真实设备突然掉电的保证取决于 provider 的持久性行为；进程 kill/模拟抛错不宣称覆盖所有硬件断电。未证实边界明确记录，不能以正常 close 后重开替代崩溃测试。

### P4：规模冒烟与手机准入

先用虚构小集做正确性，再用获准的百万字真实样本/同结构合成集测存储与恢复。5x/10x 合成放大只证明资源/吞吐，不证明真实长剧情召回质量。日志仅保留统计、指纹和合成 marker。

测冷启动、按 ID 读取、尾部/范围分页、追加、深层 edit/delete、fork、逻辑导出/恢复、块与元数据放大、峰值内存、JS 主线程阻塞及磁盘使用。报告操作数和字节数，不只报字符数。

中文文本检索可用小型人工标注 fixture 做持久性/基本检索对照；向量可用人工数值测试存取与过滤。不得把它称作已完成中文 BM25/语义质量验收；完整 E-01/T-06 与外部模型评测仍后续。

手机准入需要独立安全环境；不可用时交付只标桌面地基通过、手机 pending，不允许直接替换用户长期手机存档。后台挂起/被终止的任务应重开后可恢复，不宣称 TT 关闭后仍持续后台运行。

## 5. 验收底线

1. 已确认的 Head 始终引用完整、可验证的历史；断点恢复与重试通过。
2. 不用 embedding 也能持久保存和恢复原文/版本；正文与索引生命周期解耦。
3. 分支与来源依赖保持 T-02 语义；不同 story 不串数据，物理 ID 不泄漏为正式引用。
4. 同操作重试无重复记录；旧 Head 写入/同 ID 异内容被拒绝。
5. 逻辑导出 → 空环境恢复后的 ID、有效历史、来源关系、软删除和人工改动一致；不重新调用 LLM 生成已有正确记忆。
6. 已记录正常与故障命令、库版本、参数、实测结果、缺口；未知不写 verified。
7. B 数据结构迁移到 A 所需材料齐全；A 尚未实现时只声明迁移准备通过，不声称 B→A 真迁移通过。
8. 选型、单端边界、备份/恢复与安全升级流程已审查；未经允许不覆盖真实库、不改生产配置。

## 1. 用户目标、完成线与不做

让用户不依赖柏宝书继续运行，也能在自己的Mnemosyne档案里找一句原文或一个名称，查看准确的原文版本和邻近上下文、区分旧摘要来源，并导出可恢复档案。搜索是用户手动发起，不是模型自动召回。

完成线：在获准隔离环境通过实际工作台完成“选择已导入档案/分支 → 手动检索 → 分页/继续查找 → 查看该版本原文与旧摘要 → 安全定位宿主或档案内回退 → 导出完整恢复包”。T-04的导入/存储复用，不以重新导入私人样本或重跑规模评测为前置。T-05由Chat验收后，S-B才可在受控范围收口。

不做：向量/BM25/RRF/rerank、查询改写、LLM/embedding调用、新摘要/实体抽取、注入、世界书联合检索、按持有人查物品、全文检索服务器、模糊身份合并、AI编辑/撤销、内容修改、GC、A服务或第二provider。不因一个搜索页面重写分页树/发布协议或建设完整管理后台，不创建/执行T-06。

## 3. 已冻结的产品规则

### 3.1 范围与显示身份

默认当前已确认绑定的Story/Branch、当前已发布Head中的正文。没有绑定或有多个可能档案时由用户选择，禁止按同文/文件名猜归属。档案可脱离当前TT聊天阅读；用户显式选择的档案不随宿主切聊天偷偷改变。

搜索所有已归档原始消息（含User、Assistant、system/other、开场白），不把“User不单独摘要”误解为不查User原文。仅扫描所选历史清单成员及其指定Revision，不能遍历整个revisions表后把父线未来、旧swipe或删除版本混入默认结果。正式SourceMessage/Revision/Snapshot身份贯穿结果、详情和游标；楼层只展示。区分档案中的顺序位置与原宿主0-based楼层，续聊offset、删除平移和分叉后不得混用；映射不确定就显示档案序号，不造TT楼层。

首版一次只选一个分支/快照，不做全库跨故事联合搜索。可显式选择该分支保留的旧快照查看旧Revision/删除前历史，始终有“历史档案，不是当前剧情”标识；默认不选旧快照。切换范围撤销旧查询，不恢复/回滚Head。

绑定partial/pending/paused时展示真实进度及原因，不把最后确认档案称为已经与TT同步。可由用户显式查看“最后确认的已发布档案”，不解除暂停、不发布pending、不把它当完整当前源；不存在已发布档案时不给虚构空库成功。

### 3.2 匹配规则

查询按钮/回车显式启动；不按每个按键扫描，不后台反复自动重查。首版采用**单条消息内字面子串**查找，一句原文和名称使用同一规则；不跨消息拼接命中、不解释正则/SQL/高级语法、不做错字/语义纠正。空查询或规范化后为空不扫描，可用独立分页浏览入口看档案。

默认容错模式严格沿用11第7节：Unicode NFKC → locale-independent case folding → Unicode White_Space连续空白折叠为一个普通空格并去首尾；查询与内容用同一版本规则。原样精确模式为未经这些转换的字面子串匹配。不能把普通toLowerCase偷偷当作完整case folding；实现说明固定Unicode/映射来源与运行时兼容性，用少量代表字符验证，不建设自己的Unicode框架。

不删除全部空格，不一概等同所有中文标点，不做繁简/同音转换。原文、原身份指纹和已有摘要不改写；规范化缓存键至少含正文Revision、规范化规则版本。规范化可能改变长度：没有已验证的原文偏移映射时，只标“规范化命中”并展示原文/安全片段，不强做逐字高亮；禁止直接把投影偏移套到原文。

正文结果按该快照消息顺序稳定排列；同一消息先返回一项，不因多次出现同词生成大量重复行，不伪造相关性分数。结果展示匹配模式、角色/位置、片段及精确版本。缓存淘汰不影响档案正确性。

### 3.3 摘要辅助与来源对照

默认搜索类型只为正文；用户显式开启“旧摘要辅助”后，可查询/查看summary、higher桥接资料，单独标注类型、来源声明、scope、原floor或已记录范围，不能算成正文命中，也不转成正式TurnMemory/有效召回事实。

当前视图只采用能核对到所选分支及快照作用域的资料；不以assetMap存在、楼层相同、同Story或parent关系证明当前有效。不同/较旧scope只能另作明确历史资料查看，不能无标识混入当前结果；不得继承父线未来摘要。未证明完整生成输入时始终显示旧资料声明，即使正文锚可定位也不能把锚说成完整生成证据。

有准确锚/来源关系才展示对应原文与邻接；无原文或关系不能证明时保留摘要，显示“来源关系未证明/无可追溯原文”，不按楼层/描述猜内容。缺失本应存在的正式引用要报数据错误，不降级伪装“无原文”。不导入新的可选类别，不专门实现物品/人物/设定搜索页面。

### 3.4 宿主跳转与导出

始终先提供独立的Mnemosyne原文详情；跳TT是增强而非唯一详情入口。仅通过核对过的当前安装版公开能力，按作用域稳定身份、locator、映射与当前文本/版本证据定位；定位过时/旧Revision与宿主现文不同时，不把现在同号楼层当成旧原文。改名遵守T-04确认过的alias；不得为搜索自动重绑。

首版优先当前已打开且能核验的宿主聊天。跨聊天跳转需可靠公开能力且由用户明确点击，不能暗切聊天、自动触发导入/同步；没有可靠接口或定位已变时明确降级为档案内详情。缺宿主/缺柏宝书不影响独立档案检索。降级路径是验收内容，不要求用内部DOM猜测/脚本注入硬凑跳转。

导出复用完整分页恢复包与 `exportSnapshot`；按钮明确是“完整库恢复包”，不要暗示只导出当前搜索结果/分支。不得用会遗漏bridge材料的logical v2小包冒充备份。捕获的是导出时固定checkpoint，后续源追加不改变本包；若做核验，比较该checkpoint，不比较后来最新源库。

不重造备份协议或为本卡重新迁移25条私人样本。下载路径有字节/缓存上限；尽量流式消费，不能无上限把全库攒进JS数组/DOM。现有环境仅支持有界小包时如实拒绝超限，未完成的文件不叫完整备份。查询/导出不得联网发送内容。

## 4. 工程顺序：高难先行，单卡完成

### W0：最小读入口与状态隔离

先核对运行中扩展/owner与固定接口，复用受控库的唯一协调器。工作台查询不得调用业务prepare/execute，不因pending存在而替用户完成导入；提示回导入入口处理即可。打开/恢复可能含open/flush，不能误称绝对零物理IO，但不得改变业务Head/view/回执或清库。

导入页与工作台共存时按已有owner队列接入：搜索取消/关闭只撤销自己的读会话和监听，不能关闭别人仍在使用的写入owner、另建竞争native handle或调用TT维护接口。需要小型读facade则在开工范围里写清，不重造生命周期管理。

### W1：固定版本查询、游标和有界扫描（本卡最高风险）

查询会话至少固定库身份/读连接代次、Story/Branch、snapshot、读取checkpoint、query/mode/类别与规范化版本、界面请求代次；当前宿主跟随模式还需绑定/观察代次。游标只能用于原会话，不跨库/分支/过滤条件重复用。

工程首选：沿指定snapshot的range逐页取原文，页内生成搜索投影并作子串匹配。每次“查找/继续”限定结果数、扫描消息数、读取/文本处理字节、时间和缓存；开工给出小型默认值及停止状态，不靠长性能实验选择参数。到限返回“本批未搜完/继续查找”及进度与游标，而不是全库0命中；只有真正穷尽指定范围才称无结果/总数已知。单条超长消息也要受字节预算约束，明确未检查范围或提供有界后续阅读，不静默跳过后称全部搜索完成。

查询、翻页、打开详情、点击来源跳转均核对请求仍属当前UI/绑定及档案版本。在批次开始和返回/渲染前验证一致性；多个分别串行的await不是统一快照。首次可保守采用捕获checkpoint、末尾不相等即标过期并要求用户重查；不要先加入复杂MVCC。固定旧snapshot的历史阅读不随当前Head变化改写原文，但回执/摘要等可变索引仍须保持一致。

同步/纠错/删除/切库发生时，旧结果不再冒充当前；保留的结果只能标为旧快照。取消不再调度下一页，不无限自动重试/自动重扫；正在执行的原生调用按既有队列排空，不用Promise.race解锁。规范化/读取缓存只能复用相同数据版本及规则，不能复用上一聊天同楼层结果。返回前状态检查后，UI仍需请求代次校验，防迟到覆盖。

### W2：详情、旧摘要和可信来源

按3节将摘要辅助接入受限枚举；禁止无界扫描全部manifests/asset历史后一次性过滤。必要时增加带前缀/游标的小型只读枚举，但不得改数据主键或取消scope判定。详情和邻接只读命中的固定snapshot，跨块取值不越过选定分叉/截止。为续聊offset、删除平移、历史快照与未知摘要来源设置明确显示/跳转降级。

### W3：最小可操作页面与导出

页面仅需：档案/分支及当前或历史快照选择、状态栏、查询/模式/旧摘要开关、查找/取消/继续、结果列表、原文与摘要对照、宿主跳转/不可用说明、完整库导出。标签优先现有可读来源信息，必要时加短ID；不要求用户日常手填UUID，不为命名系统新建实体模型。

读不到当前宿主时仍可选已存档案。布局可缩放、可滚动，不遮住关闭/取消；浏览器小视口可以检验布局但不等于手机实测。正文/摘要作不可信文本展示，默认textContent/安全转义；不渲染可执行HTML，不把命中或原文写进控制台/仓库。

完成端到端路径后才做简单布局和说明；不扩建主题系统/全工作台。按本卡有限风险集合交一次实施回报，保持implemented_unverified，等待Chat验收；不自动开展T-06/T-07。

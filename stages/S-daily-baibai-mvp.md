# 日用初版阶段：柏宝书前端 + 可迁移记忆库 + 事件链

更新：2026-09-23。状态：产品范围及下述明确规则accepted；具体schema/参数和自定义表最小实现范围proposed；无正式施工卡，未实现或验收。不是自动启用旧T-06/T-07，不撤销S-A/S-B历史验收。

## 起点与已确认事项

实施基础为`Roballz/ST-BaiBai-Book` / `codex/item-keywords-presence`，前轮固定源码393873a。用户已在TT手机版日常使用并反馈流畅；旧Mnemosyne Demo的读写放大不是IndexedDB或柏宝书模式的问题，修复旧Demo不作为本阶段前置。

首版使用本机IndexedDB可迁移库，保留柏宝书前端、摘要/动态状态和现有混合召回/原文升级；按需替换正文/摘要存储、身份和接口。事件表、手动关联、事件链召回进入初版。VPS、新前端、独立实体状态库、多主同步及通用因果图不在当前范围。

最新明确规则：

- 事件整理AI读取当前合法范围的全量事件目录，不先检索6～10张候选卡。
- 概述正文只追加；一批五条相关摘要可用一到两句进展概述，但五个摘要关联均保留。元信息更新与历史概述追加分开。
- 提供独立事件LLM途径，按可调间隔（用户举例30/50楼）批量整理并可手动补齐；该任务只做事件，不重复生成摘要或结算状态。
- 三条召回规则accepted：每链至多额外一条进展且避免重复；同链合并一次包装；概述/进展/序号/总数使用同一分支和历史截止点。
- 自定义表已入产品需求，允许仅本地前端持久化，不以远端同步为条件；首版最小编辑/AI填写范围仍待收口，不擅自扩成完整无代码数据库。

入口：`../docs/13-daily-memory-mvp-proposal.md`；事件当前规则：`../docs/14-event-chain-mvp-proposal.md` v0.2；批量源码核验及自定义表建议：`../docs/15-event-batching-and-local-tables.md`。旧“候选检索/滚动覆写概述/只能每轮随摘要更新”不再是当前方案。

## 目标和收尾

沿用熟悉前端日常试用：正文/摘要独立增量入库；既有召回效果不回退；事件按链折叠、分页看摘要、人工改关联；概述形成可追溯的追加简史；独立任务按实际来源版本处理未整理范围；事件召回保持有界。

建议收尾包括可安装产物、重开/切聊天不串档、编辑/swipe/回溯不混入未来事件材料、保存失败不冒充完成、批量停止/恢复、全量目录预算有提示、另一独立实例恢复后身份/关联/进展段和任务回执不丢。仅有导出没有恢复不算可迁移。

包内需说明正文/摘要/事件/自定义表与聊天delta、知识库的包含范围；不导出密钥。新增自定义表不强制把现有物品/地点迁成另一套实体系统。

## 仍需收口的方案

追加简史的短召回投影（建议起始段+命中批次段的有界节选，不称完整总览）；明确计数单位和默认间隔/延迟；事件进展段/关联/处理回执的schema；本地自定义表首版最小编辑与AI填写能力。每轮最多扩展两条链等数值仍属建议，不因用户确认三条规则而自动冻结全部参数。

批量进度必须与摘要进度独立；明确无事件可以完成，缺字段/失败不能冒充无事件。游标便于续跑，但已处理证据保存实际ID/版本，不能仅比较总楼数与最高楼层掩盖编辑或空洞。

当前不需要用户提交真实聊天、密钥或电脑实机材料才能讨论。旧摘要事件补齐由用户选择范围，不默认全库付费重摘，不重复状态delta。

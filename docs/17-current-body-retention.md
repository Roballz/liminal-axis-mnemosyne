# 当前正文保存策略

## 范围与状态

本次用户需求取代 Daily MVP 对每次正文编辑保留完整历史的策略：每条分支只保留各条消息当前选择的完整正文，编辑、swipe、重生成后更新当前选择；多线剧情由显式分支存档承担。本策略不删除摘要、事件或表格版本历史，不改变它们的来源有效性条件。

这是本地实现说明，不代表已发布或手机已验收。真实数据库不在开发测试范围内。

## 正文与来源证明

- 消息稳定 ID 仍是身份，楼层序号不作为主键
- 新 `source_revisions` 使用 `bodySchema: 1`，只保留版本 ID、角色、来源、正文摘要哈希与长度；不再存全文
- `source_bodies` 以 revision ID 保存当前完整正文。完整载荷由同故事所有现存分支的当前 Head 联合保留
- 某分支修改消息时更新自己的 Head。其它分支仍当前选择的旧版载荷不受影响；分叉共享来源身份与完整载荷，后续选择独立
- 被摘要、事件、表格、审核或分叉使用的来源证明可继续保留，但这些历史证明不构成旧正文载荷的保留理由
- 若重新选择同一条消息的相同角色/正文，且来源证明仍存在，复用其版本身份，并从宿主当前正文重新提供载荷。这样既有来源有效性和表格 swipe 匹配不会被随机新 ID 破坏
- 已删除起源档案的来源回执可能继续保留小型版本证明，作为来源绑定回执的见证；此例外不保留无分支当前使用的正文

新正文载荷的增长上界取决于所有分支当前正文的并集，不再取决于同一楼编辑次数。源身份映射、摘要、事件及用户明确保留的表格历史仍可能增长，不能称为整库固定大小。

## 快照与 swipe

新快照 `snapshotSchema: 2` 以 `previous: null` 发布当前 Head；不形成每次观察的永久前驱链。必要业务记录引用的旧快照保留，无引用的新格式旧快照在同一次事务内退出保存。

每个来源块最多 128 条，swipe 标记与对应来源在块内对齐。未变块复用，不再为每次编辑持久化全楼层的 `variants` 数组。捕获视图可临时展开 variants，磁盘新快照不保存该整段数组。

来源证明仍不可变。不能原地改写旧 revision 的正文含义，或用同一个固定 Head ID 隐瞒正文变化。Head、view、epoch 等并发检查继续有效。

## 删除与回退

删楼使相应正文退出该分支当前选择；别的分支仍使用它则保留。表格历史继续使用来源前缀和 swipe 身份判定回退状态。

重复正文编辑如果一直对应同一个已采用的表格回退状态，不重复产生空 restore 记录；真实表格写入和之后发生的真实回退仍记录。切回旧正文恢复来源有效性，不自动复活已放弃的表格写入。

旧快照可能只剩来源证明。请求未保留的历史正文会明确失败/显示“此旧版正文未保留”，不以当前正文代替历史，也不把来源证明当作可展开全文。

## 旧数据与包格式

- IndexedDB 版本从 2 升到 3，仅新增 `source_bodies` 存储，不自动清理旧记录
- 当前导出包版本 13（1.4.0 为 v12）；v13 增加显式的摘要生成来源缺失声明，见 [摘要来源恢复](20-summary-source-recovery.md)。旧版程序拒绝不认识的新包，不提供不安全的原地降级
- v1–11 导入仍受支持，旧正文、快照、表格历史原样保留。第一次真正改变旧 Head 时，分支用 `legacyHead` 固定旧历史链
- v12 核心包继续受支持；摘要来源恢复不增加对象存储，IndexedDB 仍为版本 3
- 旧库的历史瘦身不是本次升级行为。必须另行预览、验证完整备份并取得不可逆删除授权
- 校验当前每个来源的完整载荷、哈希、长度和身份；历史载荷允许缺失只针对明确的新格式证明。拒绝当前载荷缺失、额外历史载荷、伪造/孤立引用
- 角色修复的旧/新格式混合证明在导出与恢复时临时计算旧正文摘要用于校验，不改写旧记录

## 原子性与性能边界

新载荷、来源证明、Head 更新和本策略的退出保存处于同一 IndexedDB 事务。写入配额错误或退出保存阶段异常会一起撤销，不以先删除旧正文腾空间的方式重试。

当前实现只写变化的载荷；安全引用检查读取同故事的快照、块与业务证明，成本仍随保留的元数据量增长。它不加载旧正文副本来判定回收，但并非恒定时间算法；真实 Android/TT 性能尚未验证。

## 宿主生成边界

存储层接受经过适配层确认的当前观察，不依据正文包含 500/502/429 判断是否是错误。已核验 TT 版本能把 API 错误转为普通 assistant 内容，结束事件或 `isFinished` 单独不能证明成功。适配层的暂态/中断隔离必须保持当前状态不可用的含义，不能默默把上一次归档正文当作当前剧情。

本文件不承诺可靠识别所有旧的未标记半截回复；没有宿主结构化结果信号时，错误文本识别仍存在边界，需明确提示而非删除宿主内容。

### 回复隔离与人工确认

当前适配层记录无正文的版本化宿主收据，并只镜像到当前 swipe 的 extra；它通过宿主正常保存路径持久化，不属于 Mnemosyne 核心包的宿主聊天备份。已知 pending、aborted、未知收据版本或正文摘要不符的候选，不会因重开、复制聊天或改名而变成已确认正文。已确认且内容匹配的消息可以正常移动楼层、改名或分叉。

遇到未确认候选时，整份当前观察暂不发布，状态为“回复未确认 · 暂不归档”；不缩短楼层，也不把旧版当前投影继续当成已确认的新剧情。

用户按停止后保留的片段，需在宿主编辑器真实点击/触摸确认保存后才能作为人工选定正文。只打开编辑器、自动宏/正则改写和普通 MESSAGE_UPDATED 事件不构成人工接受。键盘触发的合成保存、其它扩展的保存方式和原生 TT 现场行为尚未验收。

错误标记检测仅识别英文或当前语言的精确 TT 标记行，包括追加在部分正文后的标记。它是保守提示而非错误真值：故事中引用同样标记也可能被暂缓，未标记或其它形态错误仍无法可靠识别；不会因出现 500、502 或 429 等数字就排除正文。

### v1.4.9 原生保存时序

用户在原生楼层编辑器确认保存后，完成性门禁仍核对同一聊天、消息、楼层、swipe 与准确正文。若本次生成已经由匹配的处理器和收到的回复证明结束，即使 UI 停止按钮没有发出 ENDED，明确保存也可将选定正文记录为 edited；仅处理器为空、文本没有错误标记或旧处理器已结束都不构成接受依据。实际活跃处理器始终阻止接受，异步计算期间换聊天、重新生成或替换确认都会撤销本次结果。

编辑摘要弹窗在 EDITED 时撤销旧选择，等对应 UPDATED 完成并核对上下文后再加载最新审核项；不以固定延迟代替保存完成。延迟结束通知不能重新打开已延后、关闭、切聊天、重新生成、切换 swipe 或被新编辑替代的弹窗；排队和异步读取期间同样撤销。上述确认只恢复正文归档和手动审核入口，不自动保留、重新生成摘要，也不自动确认其他错误楼层。

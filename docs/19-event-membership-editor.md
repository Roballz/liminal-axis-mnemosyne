# 正式事件成员编辑（1.4.0）

状态：implemented_unverified；未在用户手机执行。沿用 DB3 / 核心包 v12，本功能不再新增持久字段、store 或索引。

## 交互

- 改造原楼内事件按钮，并在摘要页逐楼卡复用。无成员“加入事件链”，有成员“事件链：首条名称 +N”；详情标题包含全部名称、归档/待审核状态。缓存不可验证时显示待刷新，不冒充未入链。
- 一个全局弹层：单摘要可搜索和勾选多链、取消关联、填写新链名，一次保存。取消完全不写入。此入口不生成概要、不调用模型。
- 事件页工具栏和单个事件卡提供批量加入。范围格式 `100-150,180`，包含端点，楼号按宿主当前显示编号；用户楼等没有有效逐楼摘要的楼层不成为成员。
- 摘要关键词/时间筛选，每页20条短预览，选择本页/全部匹配结果；选中稳定修订ID跨摘要页、筛选与事件链目录页保留。批量只加入一条目标链，不批量移除原有其他链。
- 可暂时收起弹层，直接在聊天已挂载的摘要卡勾选，底部显示计数；返回弹层保留选择/筛选/目标，并重新聚焦。不会强制渲染宿主全部历史消息。
- 概要仍从事件页手动/AI更新、重写、自动或批量整理。新建链的概要、整理范围及最新进展为空，不编造已有剧情概要。

## 身份与事务

正式成员依据 `eventView` 当前分支投影，按摘要 family 解析保留关联；生成标签 `tags.eventIds` 在归档核验后幂等登记为 AI 成员；人工解除关联按摘要 family 保留，后续归档或摘要修订不自动恢复。归档、来源阻塞及概要待审核的链仍可显示成员。高层压缩总结不当作逐楼摘要，也不与子摘要一起计数。

打开单卡前固定被点击的宿主叶子ID，异步完成后再核对卡片存活、当前叶子、宿主scope/版本/generation、库及分支。多选中途的聊天/来源变化在写入前拒绝；切换聊天会清空会话。无效摘要允许解除已有成员关系，不能新增。

`saveMemberships` 先验证当前逐楼摘要及有效性、分支链、去重和变化；在一个IndexedDB事务内再核对branch story/head/view/epoch与宿主guard，写入所有链/修订/增删成员，仅推进一次epoch。最终guard失败使整个事务回滚。重复加入不创建无意义修订，取消无写入。关联版本使用当前保存时刻的snapshot/cutoff，不把重建关联伪装成过去已存在的记录。

## 读取与性能口径

选择器的打开使用 `readDailyMembershipContext`，只复用已验证归档上下文，冷/过期缓存明确要求等待正常归档完成。选择器不调用 `syncDaily` / `capture`，保存后仅刷新派生投影。测试对实际 `source_bodies` / `source_revisions` get 计数，打开、成员写入和刷新均为零。

成员小提示在既有 `projectEvents` 中由全部合法卡片生成共享映射，不能复用会过滤待审核链的召回目录。每个页面修订共享版本检查，楼内卡不逐卡读库。没有为了反向成员查询新增索引或迁移。

此口径不是完全流式档案：正常归档仍有原有全范围成本；回复终态检查会核对宿主内容，hostVersion仍序列化宿主全文，事件/摘要投影仍覆盖当前范围。分页限定新增DOM和预览，不代表Android几千楼内存/滚动性能已通过现场测试。

## 1.4.20 标签编辑统一

摘要标签弹窗与“添加事件链”共用 `readDailyEventEditor`，从已核验归档读取完整目录，包含归档和待审核链；每次打开固定视图，保存校验同一分支与版本。搜索和显示更多只控制 DOM 数量，不缩小目录范围。

“相关事件”的显示与勾选以正式成员投影为准：从事件链加入摘要后，无需再次生成摘要即可看到关联。手动勾选/取消使用同一成员事务。反向显示不向宿主批量回写标签，不制造双向同步循环；生成入口继续只输出 `tags.eventIds`，不增加模型字段、数据库 schema 或迁移。人物/公开等摘要标签仍按原流程保存。

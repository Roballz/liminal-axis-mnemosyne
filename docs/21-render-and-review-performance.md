# 历史楼层渲染与摘要审核的性能边界

## 问题证据与范围

Mnemosyne 的宿主事件监听在插件面板关闭时仍工作。加载历史楼层可能连续触发 `CHARACTER_MESSAGE_RENDERED`；1.4.0 / 1.4.1 路径对每个通知重复做全聊天比较、派生状态重放与楼层面板刷新，因此只优化摘要页不能覆盖聊天页的开销。

独立的合成大聊天检查中，155 条各约 10,000 字的消息连续发出 155 次无正文变化的渲染通知：原桥接路径做了 310 次全宿主序列化，累计处理约 4.83 亿字符。1.4.2 候选桥接路径立即序列化 0 次，窗口结束后 1 次；桥接加摘要引擎的组合回归为 2 次比较和 1 次派生重放。组合计数包含派生状态的桥接通知，不能与桥接单独计数混用。

这些是源码与 Node/fake 宿主的确定性操作计数，不是 Android 耗时或内存测量。用户关闭 Mnemosyne 后聊天恢复流畅的现象支持继续排查扩展路径，但不能据此宣称已在手机上确定唯一原因或验证修复。

## 1.4.2 候选处理

- 历史渲染通知按首个通知起的 32ms 窗口合并，窗口结束读取最新聊天；连续通知不会无限推迟截止点
- 楼层卡片刷新合并为一次可见 DOM 扫描和共享更新；155 次渲染通知的合成测试从 155 次扫描/更新减为各 1 次
- 宿主替换楼层节点时先卸载旧 Vue 应用，聊天切到排除范围也清理旧卡片；切聊天、重新绑定和页面离开清理监听与定时任务
- 自动归档最多保留一个排队或执行中的任务和一个“需读取最新状态”标记，不在慢写入后累积无界队列；页面离开前已排队但未开始的任务不再执行
- 摘要审核一次只读一个视图，途中变化只保留最新重读；一个在途读取加四次状态变化的合成场景由五个并行读取改成一个在途加一次最新读取
- 楼层抽屉关闭时不挂载变更详情，摘要预览最多 240 字；审核列表关闭时无条目 DOM，展开后每页 10 条，翻页不重新读取宿主全聊天
- 批量人工确认先显示忙碌状态，再进行当前来源校验和一次原子保存；155 条摘要不重复复制 2,000 楼来源前缀，不逐条重放或同步

## 不能被合并的边界

渲染通知是显示事件，不被用来缓存或放宽授权。编辑、删除、swipe 仍及时撤销旧的可用视图；pending / aborted 回复仍不能归档或注入。真实生成前的直接 `syncDaily` 仍被等待，读取和验证最新正文，不等渲染定时器。正常生成、swipe / regenerate 的门禁与 quiet / continue / impersonate 的既定分流不变。

已经开始的底层写入不能靠取消定时器撤回；现有提交前校验继续保留。自动队列取消不宣称终止在途 IndexedDB 操作。真实正文变化时所需的完整读取、正文保存和既有来源检查仍有成本，本轮没有改写当前正文回收算法、备份节奏、模型或权限。

## 后续现场证据

1.4.2 更新后用户仍报告约 30–40 秒出现全局卡住；进一步对照中，只关闭自动备份、保持插件启用后稳定。因此本页的渲染操作计数不能证明已解决该延迟卡死。1.4.3 另行修复核心包校验中的历史链与共享摘要依赖图重复遍历，证据及未验证边界见[备份校验性能边界](22-backup-validation-performance.md)。不把新发现回填为 1.4.2 已通过的手机结果。

## 现场验收与回退

本版本仍为 `implemented_unverified`。更新后需要在同一手机、同一聊天、相近可见楼层下对比：扩展停用时、启用后仅聊天页滚动、打开摘要审核、关闭后继续聊天。先确认聊天页不会持续卡住，再核对摘要按钮的数量、取消行为和一次明确人工确认结果。只需提供是否卡顿、可见条数和错误文字，不需要上传私人正文或核心包。

暂时停用整个 Mnemosyne 扩展会同时停止它的注入、归档和自动备份；保留宿主聊天、当前库和已有包，不清库、不反复继承。1.4.2 沿用 DB3 / 核心包 v13；代码回退不等于数据降级。完整检查与已知限制见[本轮回执](../notes/v1.4.2-bulk-summary-render-review.md)。

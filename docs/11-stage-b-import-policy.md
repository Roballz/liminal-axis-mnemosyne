# Stage-B：只读迁入、人工确认与搜索边界

日期：2026-09-21。状态：需求已确认；下列工程基线按用户授权选定，尚未实现或验收。

依据：用户本轮逐项答复；T-02 的 06/08 契约；T-03 最终回执 `notes/t-03-capability-final-review.md`。本文件细化 Stage-B，不重开已验收的 Head/Revision/分叉模型。与早期 roadmap 的“服务器同步、Leaf、全量状态迁移”措辞冲突时，以本文件和当前任务卡为准。

## 1. 阶段完成线与明确不做

Stage-B 包含 T-04 只读导入/对账、T-05 人工原文搜索与最小工作台。目标是得到自己的可恢复档案，尚不是自动记忆产品。

T-04 的同步指 TT/柏宝书 → Mnemosyne 的单向影子同步，在 B 本机存储中执行；不是 TT 数据库跨设备同步，也不是先搭 A 服务器。不注入、不调用 LLM/embedding/rerank、不写回原聊天或柏宝书、不强制安装柏宝书才能导入正文。

T-05 是用户手动搜索；T-06 才实现向量/BM25 等自动召回。两者均先聚焦剧情资料，不能把导入能力当成知识库联合召回已经完成。

## 2. 导入白名单：迁资料，不照搬旧模型

| 层级 | 本轮决定 |
| --- | --- |
| 必做/默认 | TT 原始消息正文、已有有效剧情摘要；已取得且来源明确的高层总结保留，不为导入重新调用模型 |
| 次要/可选 | 物品、地点、生活小档案；默认不勾选，用户可在导入预览选择。实现最薄的原样资料承接，不做专门实体业务 |
| 不导入 | 眼下局势、主角/人物/NPC 档案、变量树、计划、现有 embedding/向量索引、模型密钥及旧插件注入配置；未列明类别默认不导入 |

“人物不导入”指旧人物档案分类，不是从正文/摘要中删掉人物名或人物事实。生活档案里的 subject/name 属于该条来源信息，可以保留；不能为了接收生活档案而自动导入全部 NPC 档案。

保留完整原文字符串、来源角色和必要的宿主映射。柏宝书清洗 body 只作为有标签的投影，不能替代 TT 原始正文。只选允许的旧资料字段，不把 getSnapshot()/delta/extra 整个塞进目标库而绕过白名单；用户保有的原始备份文件不等于本系统授权复制全部插件元数据。

原样保留的次要资料应携带旧类型、来源标识、抓取版本/时间、内容指纹和可用来源声明。它们不是 Mnemosyne 最终实体 schema。无原文明确定义为 derived_only 或桥接资料，不能伪造 SourceRef。若采用新的桥接记录包，须有版本、重入幂等和导出恢复覆盖，不能藏在不可备份的临时内存中。

物品当前持有人、原所有者、保管人、转交历史未来应能由正式实体关系表达；本轮只记录这一需求，不强定所有权 schema。不从旧描述自动猜持有人，不改写旧物品描述，也不在 T-04 承诺按人物列出物品。

## 3. 原始消息、旧摘要与配对

原始消息逐条无损保存，User 不单独生成摘要。已有摘要沿用原文字，不改变已发生剧情。界面以 Assistant 宿主楼层作为普通回合的展示锚，User 仅作为来源之一；楼层从宿主 0-based 规则显示，不成为正式 ID。

用户提出严格交替与宽松聚合两个备选；Stage-B 采用较小、兼容当前契约的严格承接基线：只有明确的一条 User 紧接一条 Assistant，才自动承接为普通 TurnMemory。连续 User、额外连续 Assistant、夹杂 system 等不擅自拼组、不取最后一个 User 后静默漏掉前面 User；相关回合标为待人工处理。开场白、未回复的末尾 User、system/other 原文照存，不能因此判整个档案损坏或拒绝原文导入。

不能确认为 TurnMemory 的旧摘要仍可按来源可用性作为旧 Summary/桥接资料保留，不冒充普通回合已配对。不强迫用户为了导入去改写自己的历史，也不替宿主/模型转换请求角色排列。宽松多 User/多 Assistant 分组不是 T-04 必做项；未来启用时须与 06 的 TurnMemory 校验一同明确版本化。

只依据楼层号不等于证明摘要生成来源。结合宿主聊天身份、当前 swipe、柏宝书有效性标记、来源范围和稳定读取结果进行可说明的承接；无法证明则保留原资料/来源声明，不把猜测写成强版本引用。`memory.valid` 是旧插件的有效性声明，不是对所有外部编辑或隐藏生成输入的独立证明。

生成新摘要留 T-07。记录用户期望的有界输入：摘要指南与格式提示词 + char description + 角色绑定/用户选定世界书 + 本轮正文（常规 User+Assistant）。角色卡/世界书是设定上下文，不因此成为已发生剧情；实际发送的内容应可追溯到版本/指纹，不另造字段级依赖系统。T-04 不读取全部世界书来做摘要，也不付费重摘旧记忆。

## 4. 身份识别：精确证据优先，模糊候选交人工

Mnemosyne 内部 ID、已确认 HostBinding、已有导入回执提供精确重入依据。内容指纹用于检测内容一致，不单独证明两个消息/档案是同一历史；搜索规范化指纹绝不能用于身份合并。

未知来源即使全文相同也只提出候选，让用户确认映射；已绑定同一来源的完全相同重试应复用 ID/结果、不新建 Head。不通过 AI、模糊相似度阈值、通用序列修复器自动决定故事归属。高阶匹配优化留 T-13/T-14 另行规划，不作为本阶段完成前置。

部分不匹配只能提交明确的变更提案；没有来源证据时不能推断“这必定是编辑/删除/分叉”。允许确认新 Story、确认继承、确认现有映射或暂缓。未决范围不能被包装成完整同步。

## 5. 两类主入口与内部映射

主界面只提供：

1. **新聊天，不继承记忆**：创建独立 Story/Branch，不复用旧派生记忆。宿主已有正文仍可作为新故事原文归档；不必删除它们。
2. **继承已有记忆存档**：选择源 Story/Branch/快照，展示实际继承范围和结果。

已有稳定绑定的正常重开/改名/编辑不反复弹这两个选项，不自动新建故事；“确认已有映射”是映射预览/修复动作，不增加第三类主玩法。

继承选项内部必须区分已确认意图：
- 接着原剧情续聊：保持原 Story/Branch；新聊天文件仅新增/切换绑定，未新增正文时不推进 Head。
- 宿主明确从中途开分支：同 Story 新 Branch，固定父快照和含端点截止；不能继承父线未来摘要。
- 来源/截止或续聊与分叉意图不明：在同一继承面板中确认“接着聊/从此分叉”和截止位置；不得因 UI 只有两个主选项就省去必要信息并猜测。

继承必须说明将继续更新哪条线或创建哪条线。不能仅凭一份文件为空判断用户意图；用户确认前不写目标绑定。无法安全自动提取 cutoff 时用人工指定，不建设万能分叉识别器。

## 6. 删除与复杂变更：人工决定，系统保留最小防错

已确认/疑似删除或复杂修改时，合并通知并显示“聊天变化，需核对”的摘要与局部差异；不做自动剧情修复、重新生成记忆或强制批量覆盖。

检测到变化与完成映射核对之间，暂停受影响绑定的自动推进和不可信记忆使用；保留最后确认快照为明确标注的旧档案。无法准确缩小影响范围时，保守暂停当前绑定，不停止其他故事；关闭弹窗不等于确认、也不解除暂停。重开后暂停原因应可恢复。

用户可以在 TT 修正后重新对账，或预览并确认 Mnemosyne 应采用的删除/局部替换。明确确认后才发布新 Head 并应用既有有效性规则；无需人手填写 UUID 或直接编辑数据库。被删旧版本仍保留，不自动 purge。

Regenerate 的中间删除/重建不能每次当作用户永久删除来报警。已知生成生命周期先标 pending，等稳定结果；不能判定则人工处理。事件只提示变化范围，订阅不是可靠增量日志。自动路线上只做精确、局部的对账；漏事件/外部编辑保留手动重新核对入口，不承诺无条件实时检出。

用户决定剧情如何改和如何修正内容；程序仍负责不丢数据、不串分支、不静默使用已知过期结果。不能把这些基本正确性义务转嫁给用户。

## 7. T-05 手动搜索范围与匹配

默认当前 Story/Branch 的有效正文；旧 Revision、删除历史、其他分支不混入默认结果。摘要为可显式选中的辅助资料（包括有清楚标识的无原文摘要），不冒充正文命中。物品/人物/世界观的专门检索与按持有人筛选留后续实体/模块功能。宿主定位不可用时展示 Mnemosyne 保存的原文并说明，不能猜跳别的楼层。

采用可重建搜索投影，与原文/身份指纹分离。工程基线：Unicode NFKC + locale-independent case folding + Unicode White_Space 连续空白折叠为一个普通空格、去首尾空白；不默认删除全部空格，不做错字/语义纠正、不把所有中文标点都视为相同。NFKC 还会折叠部分兼容字符，因此保留原样精确匹配方式，结果标明规范化命中。规范化改变长度时不得直接把投影偏移当原文偏移。

这是 T-05 的后续实现要求，T-04 只保全材料与角色/来源，不实现搜索引擎。向量/BM25 的候选源、语料分类和有效性过滤在 T-06 接线；增加知识库不只是把所有文本无条件混在一起。

## 8. 测试与尚未授权的范围

按验收场景而非用例数量规划：短反例/受影响回归先行；候选稳定后一次全量。文档变更不重跑；无代码变化、无新失败依据不循环重跑。完整日志落文件，仅给摘要/失败段。不要为了追求测试数量自行增加重复变体、性能矩阵或反复读取旧日志。

T-04 不跑旧机1x/5x/10x、不做性能调参。现有隔离条件内的小型功能演示允许按任务执行；预计超过5分钟的原生循环、新的强杀/破坏性验证或更换设备/安装需先说明目的与停止条件并取得许可。预算到点停止发起新操作，正在发生的写入仍须按既有未知结果/恢复协议处理，不擅自并发重试或杀进程。

T-03 的 `HOST_MAINTENANCE_UNSUPPORTED`、生产手机 pending、未经授权真实资料和付费 API 禁止均保留。只读源端不等于目标端已取得生产维护安全性。代码/功能可以在受控副本完成，不能暗中授权真实长期档案切换。

## 12. T-05实施接口（implemented_unverified）

手动读取使用队列内有界readView facade，沿固定snapshot成员扫描；checkpoint/owner代次和UI代次三处核对，变化则撤销当前结果。规范化固定Unicode17完整默认case folding数据，NFKC由ECMAScript运行时提供；投影不持久化、不用于身份/原文偏移。详细限额与超大单条未检查状态见packages/workbench/README.md。

旧摘要需所选scope及assetMap版本同时匹配；其他同分支快照/旧版本仅显式历史资料，不等于所选剧情。当前无经过验证的宿主定位适配，因此一律明确档案原文回退。完整库导出复用exportSnapshot，16MiB本地Blob上限，超限不交付半包。无业务写入/自动恢复，不关闭共享owner；这不是手机生产或宿主维护准入。

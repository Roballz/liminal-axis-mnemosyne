# 自定义表名称排序与整行注入遗漏修复

基线：`569f17690763c32a4d9ecdf32baaa1611fb917f3`，分支 `work/daily-memory-mvp-baibai`。发布版本：`1.4.34`。
状态：implemented_unverified；已完成本地合成数据、Node/fake IndexedDB 和 Vue 页面逻辑验证，未在用户 Android TT 实机验证。

## 已确认的原因

1. 表格页面与模型注入均直接使用 IndexedDB 返回顺序。同表的记录按随机生成的内部行 ID 排列，未按界面显示的第一列名称排序。
2. 表格行保存原始摘要版本 ID 作为来源。摘要只修改参与者、关联事件等标签时，canonical 会生成新版本 ID，但保留相同内容和来源证据。原注入逻辑只接受当前版本 ID，且要求行内全部来源都在允许集合中，因此会把仍然有效的整行过滤。
3. 摘要模型接收已有表格时也使用上述严格 ID 判断。原行后续更新会保留历史来源 ID，不能靠继续更新保证恢复。

已在实际 bridge 流程中复现：建立来源于摘要的 `S-002`，只修改摘要标签，正文、摘要内容和表格值不变，旧代码的 `dailyTableText()` 变为空。没有读取用户真实 RP 档案，不能将该反例断言为用户每一条遗漏的现场原因。

## 修改范围

- `table-order.ts` 提供共享的第一列自然正序：`S-001、S-002、S-010`，未补零的 `S-1、S-2、S-10` 也按数字顺序；数字列按数值排序，旧空名称置后。相同排序值保留独立行及确定顺序，不改变精确主键比较规则。
- 页面在刷新取得记录后排序一次。搜索、分页和显示隐藏行复用已排序数组。
- 正文状态注入和摘要表格提示在生成文本时使用同一排序函数。页面的 20 行分页不影响完整注入。
- `allowedTableSources()` 复用当前摘要有效性结果。对表格实际引用的旧 ID 去重、按 ID 读取，只有同一摘要且内容、来源、分支和权限完全等价的版本才可沿用。沿用现有 `sameNarrativeRevision()` 判定，不按同名或同楼层猜测。
- 完整同步、增量表格刷新和摘要填写上下文共用来源解析。完整同步的最终实时分支检查安排在旧来源读取之后，防止另一连接在等待期间推进分支却发布旧投影。
- 真正修改/删除/禁用的来源、私有来源以及一行内任意失效来源仍阻止该行注入。隐藏、删除和正文 `bodySources` 校验保持原语义，不扩展表历史恢复或角色修复规则。

## 性能与数据影响

不新增监听器、定时任务、数据迁移或存储字段，不重写现有表格行、来源或历史。

200 行共用同一旧来源的测试只读取该摘要版本一次，不扫描摘要版本全表；当前版本来源不新增查询。`dailyTableText()` 和正文注入 getter 继续只读取已发布的内存结果，连续调用不创建数据库事务。排序仅比较第一列，不序列化整行内容；原搜索缓存和无变化刷新测试保持通过。

# 核心包备份校验的性能边界

状态：1.4.3，`implemented_unverified`。本页区分用户提供的手机现象、可复现的源码问题与合成测试；没有读取用户真实聊天或核心包，也没有在手机上创建或验证备份。

## 问题证据

- 用户在 1.4.2 仍遇到启用插件约 30–40 秒后全局卡住；停用插件恢复。进一步只关闭自动备份、保持插件启用后稳定
- 自动备份原有首次前台稳定等待为 30 秒，随后完整导出并校验核心包。时间吻合支持继续检查此路径，但不是手机堆栈或唯一根因证明
- 原摘要依赖循环检查把共享 DAG 当成树，递归重走相同子图。真实逐楼摘要生成会记录此前摘要依赖；155 条、有共享生成历史的合成档案能进入此路径。先前只用 `dependencies: []` 的大数量样本无法覆盖它
- 原旧快照检查从每个历史快照重新沿前驱回到开头，长链形成二次方重复读取。较早格式的真实快照行仍须保留，不能用当前快照假装旧格式作验证

## 1.4.3 处理

摘要依赖检查采用显式栈与“当前路径 / 已完成”集合：首次访问子图时逐边展开，完成后其他入口复用结果；当前路径内再次遇到同一修订仍判为循环。遍历本身为 O(V + E)，不依赖递归调用栈。每条摘要原有的直接依赖身份检查仍单独执行，因此密集图回归计数为每条边两次：一次直接检查，一次图遍历。

旧快照前驱检查在单次校验内记住已完成的无环路径，后续只走未完成前缀。每行原有的结构、前驱存在及分支归属检查仍执行，不能因另一条路径已完成而跳过后续行的错误。

两个集合都只是一次校验的临时状态，不跨导出缓存。没有变更 DB3、核心包 v13、正文保存、快照行、摘要依赖、校验和、备份封装、调度或用户偏好。旧 v1–12 包继续走各自原有格式规则。缺失引用、循环、跨故事摘要依赖和跨分支快照前驱仍严格拒绝；不以“忽略坏历史”换取速度。

此复杂度结论仅覆盖两处图遍历。全库一致导出、正文哈希、JSON 序列化和原生文件读回仍有整包时间与内存成本；本轮未将整个备份改造成分块或后台线程，也未测量 Android 峰值内存。

## 回归覆盖

- 5,000 / 10,000 个实际旧快照行按正序、逆序输入，计数验证前驱读取线性增长；长尾进入循环及已完成路径后出现的独立坏边仍拒绝
- 30 / 155 / 1,000 节点密集共享摘要 DAG 逐边计数；20,000 节点长链不依赖递归栈，并拒绝尾部环
- v1–13 各版本保留旧行，并拒绝循环、缺失和跨分支 / 跨故事引用；校验前后包内容不变
- 保留 5,000 旧快照的合成库通过真实 `exportLibrary()`、自动类型保存、内存磁盘读回与冷恢复；该适配器不是真实 TT 原生磁盘
- 真实 `summarizeFloor` 代码路径以假模型返回生成连续 L0，另用 155 条共享历史依赖样本覆盖混合人工确认和完整导出。生成测试不调用在线模型，不能称为手机或真实用户库测试

另有真实同步到完整备份读回的合成探针：155 节点、131 个带依赖摘要、11,659 条边，以及 310 条各约 10,000 字正文，保存并读回约 10.28 MB 的内存文件用时 645ms。10ms 间隔探针的最大间隔仍达 126ms，说明去掉指数遍历不等于完全消除整包工作。数字仅为一次 Node 测量，不代表手机耗时。24 / 131 的不同合成组成用于覆盖可解释的排除路径，用户真实库组成仍未知。

精确执行数量、候选冻结摘要和生产产物哈希由[本轮回执](../notes/v1.4.3-backup-validation-review.md)记录。运行回归与保留测试代码是两件事，以回执的实际命令为准。

## 人工确认与依赖边界

普通来源待核对和缺失基线的当前 L0 可以合并确认，生成时有旧摘要依赖不再单独排除。弹窗明确说明这是以当前楼层及此前正文为依据的新人工判断；新版本用固定正文快照和自身锚点，不继承旧生成时的摘要依赖。旧版本、原依赖、来源证据和缺失声明全部保留，不能因此把原 AI 证明补成有效。

仍只接受可与当前宿主身份、文字及回复版本精确匹配的公开、启用 L0；无效、缺映射和高层条目显示排除原因与数量。既有高层摘要与事件概要按其依赖另行审核。详见[来源恢复与确认语义](20-summary-source-recovery.md)。

## 发布后的最小现场核验

1. 自动备份保持关闭，保留宿主聊天、当前库和已有包；不要为测试清库、重新继承或缩短历史
2. 确认更新到实际发布的 1.4.3 并完整刷新，先在原聊天等待超过此前出现卡死的时间，检查聊天仍能正常响应
3. 在备份面板明确执行一次手动保存，等待成功并确认新文件能读回验证；读取到旧列表或显示 0 份都不等于已创建备份。失败时保留错误文字，不反复触发
4. 只有手动路径及聊天响应均确认正常后，再由用户决定是否开启自动备份并核验首次保存。成功前不声称已恢复手机自动备份

未执行手机原生写入、低空间、杀进程 / 断电、真实资料恢复或 UI / 浏览器验收。回退代码不代表数据格式降级；保留升级前旧包和当前 v13 包，不用删历史或关闭校验规避错误。

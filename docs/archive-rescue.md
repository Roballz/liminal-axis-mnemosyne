# 只读档案救援（未做真实 Android 验证）

## 构建与发布边界

基线：`8d59735c`（1.3.15）。`npm run build:rescue` 生成独立目录 `rescue-build/`，含救援专用 `manifest.json` 和 `dist/rescue.js`。不会修改普通版 manifest、dist 或数据库；普通版构建入口不变。救援包没有普通启动模块、宿主 API、生成拦截器、更新检查、迁移或同步。不能把救援脚本热加载到普通版页面来暂停它。

发布需要另行批准。若采用专用救援分支，发布者须把这两个构建产物作为该分支根 manifest/dist 对应内容，不能只提交源文件后让用户以为已启动救援。普通工作分支的生产 dist 保持不变。安装/分支切换能力须以用户实际 TT 版本验证，不能要求手机用户直接执行下载的 JavaScript。

## 现场顺序

1. 保持原设备、原应用配置、原访问协议/主机/端口。不要卸载原应用、删除扩展、清除站点数据或 localStorage，也不要恢复旧核心包覆盖现状。
2. 在扩展管理里停用普通 Mnemosyne；停用不会终止已加载代码或在途任务。停止生成，正常关闭其他会话；关闭扩展管理器并等待 TT 自动重新载入，确认普通插件已停用。不要边生成边切换。
3. 在仍停用的状态下重新打开扩展管理器，用 Switch branch 切到经批准的 `rescue/readonly-archive-diagnostics` 分支；确认救援名称和 `1.3.15-rescue.1` 版本后再启用。关闭管理器并等待自动重新载入，关闭所有旧会话后冷启动。是否会影响 TT 其他扩展由宿主决定，救援程序不控制或声称暂停宿主。
4. 确认显示“Mnemosyne 只读救援”，没有普通记忆窗口。勾选冷启动说明后枚举。若检测到普通窗口/拦截器会锁定救援；检测不到不等于证明其他进程静止。
5. 先下载无正文诊断报告。数据库枚举不受支持时停止，不猜库名；缺失 selector 时仅报告，不创建默认库或自动选回旧库。对每个已枚举日用库手动读取数量；不会设置活动库。
6. 按需要下载所选库的私人原始救援 JSON，并检查手机文件管理器中是否真的保存成功。内容只在本机生成，可能含全部私人 RP；不要公开上传。此文件不是可直接导入的核心包。下一步恢复/选库需另行审核和授权。
7. 返回普通版会恢复自动任务，所以在排查完并明确决定前不要切回普通版。

## 保证与限制

- 每次打开前重新枚举，只允许 `mnemosyne_daily_default` 和 `mnemosyne_daily_lib_*` 类现有库；无版本参数打开。若枚举后库消失触发创建事件，立即中止升级事务。超时、阻塞后迟到的连接立即关闭；正常读后也关闭。
- 所有表只读计数。单次计数或导出各自使用覆盖现有表的一个只读事务。数据库列表和随后各库读取不是跨库全局快照；其他上下文仍可能写入，工具不能证明整机静止。
- 原始记录导出只读已知日用档案表，保留主键和值，不跑领域校验，坏引用也保留；未知表明确列为 omittedStores，不读取字体等不相关数据。不称完整数据库备份。
- JSON 使用 `mnemosyne-tagged-graph-v1` 编码，保留环/共享引用、数组空洞、undefined、特殊数值、BigInt、Date、RegExp、Map/Set、ArrayBuffer/视图及 Blob/File 字节。遇到不支持类型整体报错，不悄悄截断；没有实现导入/解码器。
- 原始数据暂存在内存；大库可能超过手机内存，导出不是流式。只读事务和 Blob 读取有超时，但同步 JSON 序列化受浏览器主线程约束；不能保证大库 UI 响应或成功保存。失败不得宣称备份已完成。
- Node/fake-indexeddb 测试仅证明合成场景；未访问用户手机数据库、未验证真实 Android 下载、TT 扩展切换或实际数据恢复。完成状态为 implemented_unverified。

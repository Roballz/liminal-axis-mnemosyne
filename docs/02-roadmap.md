# 分阶段实施计划

v0.1 · 2026-09-17 · 全部开发任务初始状态为 planned

## 1. 执行原则

不要按“写完全部后端，再写全部界面”的顺序。每阶段必须交付一个能看见、能验证、能回退的闭环。所有数字阈值都是测试配置，不是未经测量的性能承诺。

每项任务的共同完成标准：代码和文档一致；测试真实执行；异常路径有覆盖；有回退方式；没有修改用户唯一存档；能说明尚未验证的边界。

## 2. 阶段地图

| 阶段 | 任务 | 用户能获得的结果 |
| --- | --- | --- |
| A：验证接入与地基 | T-00～T-03 | 确认 TT 可对接；确定存储与身份契约 |
| B：先把数据拿在手里 | T-04～T-05 | 柏宝书只读导入、可靠备份、手动原文搜索 |
| C：可对照的自动记忆 | T-06～T-09 | 混合召回、受控状态、独立注入与前置等待 |
| D：补上用户独特需求 | T-10～T-12 | 事件关联、自定义模块、辅助编辑助手 |
| E：规模与实际切换 | T-13～T-14 | 恢复演练、长记录评测、逐类替换旧注入 |
| F：可选扩展 | T-15 | MCP 或第二宿主适配，不阻塞前面阶段 |

## 3. 可逐项交给编码助手的任务

### T-00：仓库基线与环境清单

目标：固定当前 TT／柏宝书版本、设备、主 API 类型与可合法导出的样本格式。只用虚构小聊天或用户明确批准的脱敏副本。

输出：baseline 文档、能力探测清单、需求状态确认、许可核查待办。仓库创建和公开性由用户另行指定；本任务不授权发布真实数据。

验收：能复现版本号，确认公开 API 是否存在，记录无原文／缺摘要情况。未经检查的能力必须写 unknown，不填 yes。具体工作单见 tasks/T-00-baseline-and-probe.md。

### T-01：TT 极小适配探针

依赖 T-00。只实现一个测试面板、一个可控假召回结果和一个异步生成拦截验证。与现用记忆插件隔离测试。

验收：可在隔离的 TT 测试环境打开面板，首轮以桌面端为主；能访问获准测试 HTTPS API；能够证明正文请求发生在假召回完成之后；取消后不再注入；捕获实际 user/system @d0 输出顺序。现用手机端不作为首轮破坏性测试环境，移动端验证在具备独立安全测试条件后再补。

不做：真实数据库、自动改档案、完整设置页面。回退：关闭探针扩展即可恢复旧流程。若目标 provider 无法准确表示某位置，记录限制而非硬改核心。

### T-02：身份、版本与契约样例

依赖已 verified 的 T-00/T-01/T-02A。Story、Branch、SourceMessage、SourceRevision、HistorySnapshot、TurnMemory 与 ContextBlock 的最小可执行契约见 06 v0.2；参考模型和 A01～A18 正反例已实施，状态 implemented_unverified，待 Chat review。当前 task 优先于早期路线示意。

验收：改楼层号不改变消息身份；swipe／编辑后旧版本可审计但不会自动当作有效剧情；分叉后互不串档；引用缺失明确报错；核心对象不要求作者预设成长／未来计划字段，角色心理与情感变化必须保留来源或明确证据状态。

不做：提前生成完整业务数据库和复杂图数据库。

### T-03：可迁移、可恢复存储地基（proposal，未执行）

依赖 T-02 review。按预备卡评估 B 本机 provider，保留 A 独立服务器迁移能力；先验证能力/恢复再选型，不自动建设服务器或指定数据库。须由 Chat/用户明确改为 planned 才能执行。

验收以 T-03 预备卡经 review 后的范围为准：完整 Head 发布、幂等恢复、不可变数据保护、逻辑导出到空环境恢复及设备性能；T-02 内存往返不替代这些门禁。

不做：亿字导入、全部管理页、所有检索算法。

### T-04：柏宝书只读桥接与可靠同步

依赖 T-01、T-03。用公开 API 或导出副本读取单楼／摘要／结构化状态，建立宿主映射与服务器幂等同步；本地待同步队列可恢复。

验收：同一批重传不重复；断网重开后可继续；导入报告有消息数、叶子数、来源缺口与校验；原文与清洗投影分开；不写回柏宝书。

注意：API 返回深拷贝不是增量日志；变更订阅只表示可能变化。按版本核对，不在每次变化时上传整库。回退：停同步，不影响原插件。

### T-05：独立原文检索与工作台最小页面

依赖 T-04。提供手动精确原句／名称搜索、原文对照、来源跳转和导出。分页读取，不下载全库到手机。

验收：固定原句可在导入范围内找到；中文标点／空格规范化行为清楚；无原文只能显示摘要，不伪造详情；错误聊天、无效版本与未来分支不出现。

这是第一个有实际价值的里程碑：即使自动召回未完成，用户已有自己的可恢复档案与搜索入口。

### T-06：混合召回基线与可解释 trace

依赖 T-05、BM25 中文小实验。加入一次 Query Rewrite、向量多 query、BM25、家族合并、RRF、rerank。20 个候选作为起始对照，同时限制 token。

验收：能切换 vector-only／BM25-only／hybrid 做同集评估；BM25 独有命中不会被旧 embedding 阈值全部淘汰；多个 query 不重复计算同一来源；无 rerank 时字段为 null；每次显示费用相关调用量、阶段耗时与截断。

回退：保留手动精准检索和单分支检索，不影响档案。

### T-07：叶子派生与实体状态版本

依赖 T-04。先兼容导入的叶子，再实现生成后摘要、实体抽取任务和修正队列。人／物／组织／设定使用稳定 ID 与有来源的变化。

验收：摘要失败不丢正文；重复任务不重复扣物品；用户锁定字段不被覆盖；旧楼修改触发相关摘要／状态失效；离场不推断出未经证实的实时状态。

新增事实无来源时只能标为待确认；不默认推断角色心理或作者秘密。

### T-08：常驻、激活与注入编译器

依赖 T-02、T-07。实现详情／概览／隐藏待召回，以及独立的排除与录入开关；实体名精确命中、远处实体激活和分块位置配置。

验收：隐藏但命中会展开；异地角色可被讨论激活；同名角色不会自动合并；详情常驻超预算明确阻止而非静默压缩；固定块排序稳定。

重点测试配置继承和实体字段稳定／动态拆分。

### T-09：真实生成前闭环

依赖 T-01、T-06、T-08。把远程 prepare 接到 TT await 拦截，展示召回和注入预览，并使新回复进入同步／派生任务。

验收：正文请求前已完成召回与编译；快速切聊天、取消、swipe、续写、quiet 和副 API 均不串槽；严格／宽松失败模式可见；输入变化使缓存失效。

责任矩阵明确旧柏宝书与新插件分别负责什么，不能双重注入同一类内容。

### T-10：事件关联与原文升级实验

依赖 T-06。先做手动跨楼关联、原文跨度和有界邻接；再实验自动分组。

对照：每楼独立召回；每楼召回后扩展事件；事件级候选／分组去重。使用同一 token 预算，比较证据覆盖、因果连贯和无关内容占比。

验收：一个跨四楼事件可取到前因后果；不会越过分支／秘密边界；用户可拆错组；事件包过大时透明裁剪可选证据，不丢必需的已选来源。

不做：自动把所有叶子永久合并成不可拆的大摘要。

### T-11：自定义模块与本地模式

依赖 T-08。实现 schema 驱动的表格／卡片，使用【记忆残响】示例；支持远程、本地持久和临时模式。

验收：前端新增模块不必改后端代码；改显示名不丢数据；禁上传时网络请求不包含本地记录；本地关键词可激活；导入导出保留 schema 与行版本；作者字段不进正文。

回退：导出模块 JSON，再禁用模块，不影响其他记忆。

### T-12：前端助手与变更提案

依赖 T-07、T-11。实现选择数据、指定副 API、提案、差异预览、确认与撤销；记录网络发送范围。

验收：助手未确认不能改数据；schema 不合法拒绝提交；他人或同步已改版本则返回冲突；批量重写可逐条排除；锁定字段受保护；无任意 SQL／脚本入口。

助手生成的是提案，不是可信事实。建表与字段迁移单独确认。

### T-13：规模、备份与恢复演练

依赖前述功能。准备多级数据集：开发小样本、百万字、三千万字、亿字目标集。合成数据只能测吞吐，召回质量用有标注的真实或人工剧情样本。

记录硬件、模型版本、切块数量、平均块长、并发、p50／p95／p99、前端峰值内存、首屏时间、索引延迟和恢复时间。没有测试结果就写未测，不填估算作实测。

验收：索引可重建；备份可恢复；全量导入可暂停；前端不会为一次查询读全库；大量远程记录不会自动变成大量常驻概览。TT 单聊天完整加载单独测试。

### T-14：逐类切换与发布

依赖 T-09、用户所需 T-10～T-12、T-13。先切剧情召回，再按验收切实体与模块。保留旧柏宝书备份和禁用开关。

验收：新旧数据数量／引用抽查一致；不存在重复注入；用户能从导出包在干净环境恢复；文档明确已支持的 TT 版本和 provider。

不能把无原文的旧档案称作完整迁移。许可／归属审查在发布之前完成。

### T-15：可选 MCP 与第二宿主

依赖稳定 Memory API。为 search/read/prepare 等封装 MCP，或新增另一个 Host Adapter。MCP 不另建数据库，不要求正文模型先调用才可自动召回。

验收：相同输入范围与版本能读取同一正式数据；宿主语义差异明确；主档案可独立运行。长剧情骨架算法仍需单独决策，不因做 MCP 自动解决。

## 4. 任务状态模板

每项维护 ID、状态、依赖、负责人／执行助手、工作分支、实际基线 commit、改动文件、测试、截图或 trace、已知问题、回退步骤与文档变更。使用 STATUS 值：planned／in_progress／implemented_unverified／verified／blocked。

最先执行 T-00，不要求一次做完 T-00～T-15。

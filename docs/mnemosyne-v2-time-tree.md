# Mnemosyne 重构草案 · 按剧情时间组织历史总结

2026-11-24 讨论稿。分支从日用插件 v1.4.62（d3b1138）建立。本文记录重构意向，具体预算待用合成样本和实际使用反馈校准。

## 使用目标

长篇 RP 常在同一剧情日内展开大量细节，也会在半楼内跳过数日。希望按故事内日期浏览前情，在续写时保留上一场戏的对白、条件和应答。按每现实年约 3,000–4,000 条 L0 估算，两年约 6,000–8,000 条。设计关注未来两三年的使用，聊天顶端的历史剧情总结通常争取控制在 10 万字以内，可短暂超过，最高 12 万字。预算对象是当前分支实际注入的整块历史，包含日期标签和分隔符。

## 时间树与来源

| 层级 | 剧情范围 | 归组与收尾 |
|---|---|---|
| L0 | 单个原始回合 | 保存完整摘要、稳定身份、来源版本和可确定的主线起止时间。 |
| L1 | 剧情日 | 按同一天的 L0 或其已归档的日内阶段组成；出现可靠的后续主线日期再收尾。 |
| L2 | 月内七日段 | 固定为 01–07、08–14、15–21、22–28 日，29 日至月底单列短段。显示实际日期范围，星期沿用剧情日期信息。 |
| L3 | 自然月 | 收纳本月有记录的周段和余段。 |
| L4 | 自然季度 | 按 1–3、4–6、7–9、10–12 月归组。 |
| L5 | 剧情年 | 汇总本年阶段转折、重要结果和下一年仍须承接的状态。 |
| L6 及以上 | 自选时段 | 手动选择范围，编写跨年或篇章编年史。 |

以楼层叙事顺序和当前分支的有效来源为准。回忆、梦境和书中情节按所属时间层记录，不凭内层日期关闭主线的一天。跳时留下的空白日、周、月无需生成节点。单一稀疏来源可直接沿用。日期缺失、倒退、架空历法无法定位、历史来源间断时保留原顺序和真实范围，避免编造日期或跨过刻意独立保留的卡片。旧的 L1–L5 数字曾表示合并次数；旧卡的日期语义、手选范围和来源不可仅凭层级推断。

**跨日 L0。** 一楼先写当晚、随后跳到几天后的早晨时，新版可在同一次摘要请求中标明各段对应的剧情日期，同一卡片仍展示为一条完整 L0。按日期查询时两个剧情日都能定位原卡；日总结各取对应片段，注入时每个片段只出现一次。设立和履行跨日的事项各记在实际发生日，更高层保留起点与结果。旧 L0 仅有起止标签、无法可靠切分时，整条作为跨日过渡保留一次，由能完整覆盖它的上层收纳。来源标识需能区分片段，尤其要验证仅一端已日结时的去重和覆盖。

## 日内阶段与近期细节

- 日内先试每 10 条 L0 或累计约 6,000 字（先到为准）整理一个阶段，典型 6,000 字材料约写 1,800 字。重要性决定取舍，短材料允许提前收束。保留阶段对原始 L0 的引用。
- 日总结参考当天**原始 L0 总字数的约 30%**，密集日可到约 13,000 字。20、30、70 条各约 600 字的 L0，对应约 3,600、5,400、12,600 字。每日结算只对原始材料算一次预算。
- 密集日若七个阶段各约 1,800 字，已经合计约 12,600 字，直接按顺序收进日卡即可，无需再调用模型。取消早期设想的“每三段滚动压成 3,500 字”。同一条线跨段时保留转折、承诺的条件、双方应答和重要原句。
- 当前剧情日与上一个**实际写过的剧情日**优先详细注入，可合计预留约 3 万字。跨周、跨月和中间几个空白日都不应提前淡化上一场戏。旧日可先归入三日阶段；相邻两个已完成的七日段在材料较长时也可暂合。阶段只代表对应的来源范围，不另设正式层级。
- 一个来源范围在单次注入中只出现一次。日卡已收纳的阶段、周总结已覆盖的日卡均可回看。近期日仍需详细注入时，粗摘要只能覆盖其余部分，或推迟该组收尾，避免把整周和其中一天同时注入。

## 高层压缩与总量

日以上先按长期价值筛选整件事件，再分配字数。保留阶段转折、重要历史事实与冲突证据、关系边界、未了事项和知情范围；重复过程合并，只保留能证明变化的代表细节。已提出又已了结的事项不得压成悬案。需要核心台词时仅引用下层确实提供的原句。

七日段、月、季、年的讨论起点分别为 6,000、11,000、18,000、24,000 字的密集期参考上限。普通季度约 1 万至 1.5 万字。临时三日、双周段曾按 4,500、7,500 字估算；应随近期保真窗口和剧情密度校准，篇幅少的时段直接沿用材料。旧估算以“日卡最多 3,500 字”为前提，不能作为调整后配置的峰值证明。

按最终组装的历史文本计量，10 万字附近优先整理已经远离近期窗口的旧阶段，12 万字为整块上限。超预算时需要先得到覆盖相同来源且有效的短版本；压缩失败或有效短版本不足时，应提示并保留原文和来源，不能靠截断或漏注入凑数。具体调度留到实现时确认。移动端应复用已有注入文本或增量计数，避免每次发送都扫描整库或触发模型重写。

## 重构时的兼容核对

- **事件链与自定义表复用。** 两者与 L0 来源绑定。先验证旧档映射、跨日片段、编辑、swipe、分支继承、删除和还原。日结与更高层归组自身不得造成事件失联、表行重复填写、错误失效或跨分支注入。
- **旧历史共存。** 可从新确认的完整剧情日起启用日历归组，先保留旧卡与孤立低层卡；历史回填、迁移和重建另行设计。跨日显示与检索都应回到同一条有效 L0 和正文来源。
- **正文召回。** 时间树提供日期过滤和来源定位，摘要召回与独立的原文检索并行。整楼标签、中文长短词索引、SQLite WASM 首选方案与手机验收见[手机端历史正文检索](mnemosyne-v2-fulltext-recall.md)。
- **验证样本。** 覆盖密集日 70 条以上、同楼跨日、跨月短段、缺日期与跳时、上一剧情日跨季度、季度结算前的实际注入峰值。核对材料是否完整且只出现一次，并检查 UI 线程是否因重复读取或刷新卡顿。

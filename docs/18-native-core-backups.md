# 原生磁盘核心包备份

状态：implemented_unverified。实现和合成测试不等于 Android 手机现场验收；未执行用户手机读写、恢复或清理。

- [前端适配](https://github.com/Darkatse/TauriTavern/blob/007abf7f1edfff275cf2a0182bf19179bcef087a/src/tauri/main/api/extension-store.js)

使用 `window.__TAURITAVERN__.api.extension.store` 的 `setBlob/getBlob/listBlobKeys/deleteBlob/tryGetJson/setJson`。命名空间固定为 `mnemosyne-core-backups`，文件表为 `snapshots-v1`，设置表为 `settings-v1`。真实相对路径为 `data_root/_tauritavern/extension-store/mnemosyne-core-backups/blobs/snapshots-v1/`；不硬编码 Android 绝对路径。

这是原生数据根目录中的独立文件，非 WebView IndexedDB/OPFS，也非插件安装目录。没有 HTTP 上传或云端兜底，没有修改 TT。宿主临时分块接收后原子发布单个文件；接口没有跨文件事务或断电持久化保证。原生删除没有垃圾箱。

## 触发、轮换与边界

- 默认关闭，用户在“档案 / 迁移 → 本机磁盘核心包备份”明确启用；启用说明本机明文存储和旧自动文件永久轮换。
- 前台 30 秒稳定等待后检查；正常检查间隔至少 30 分钟，库内容摘要不变不写新文件。导出日期不参与内容摘要。
- 归档 pending/error/conflict/tableError 时延后。前台隐藏或 pagehide 停止新工作，撤销后续轮换；已提交宿主的原生写入不能保证取消。
- 写入失败按 5/10/20/30 分钟退避。仅一个定时器和一次在途检查，不累积每次消息变化的写入队列。
- 每个源库独立银行：默认保留 10 份（可选 5 份）自动文件。文件名包含库哈希、时间、随机 UUID。恢复产生新库，不轮换原库银行。
- 手动保存、新起点、固定副本及恢复前保护文件不自动删除，因此多个库或保护副本会令总数超过 10；面板展示已验证文件数量和总字节。没有自动清理历史库、插件目录或用户手动导出文件。
- 只对本功能严格命名、封装归属、源库和完整校验均匹配的自动文件执行轮换。新文件完整读回验证、保留集逐份验证后才删除多余旧自动文件；任何验证或 I/O 异常都保留旧文件并显示警告。
- 全空库、领域无效包、身份减少、全量消息身份丢失仍停止自动备份和轮换。1.4.7 对可确认的正文删除/缩短增加归档前保护，详见下节；模糊变化仍须核对后明确手动保存为新起点。

## 删除前保护与继续运行（1.4.7 候选）

自动备份启用时，桥接在同一 source-sync 串行队列中比较当前库的绑定、Head 消息身份和待归档宿主观察。只有发现消息消失或同 swipe 正文缩短才导出完整包；在 `synchronize()` 发布新 Head、清退当前正文之前完成原生文件写入及完整读回验证。它保存的是这一刻**当前已归档核心库**，包括比最近 30 分钟自动备份更新的已归档正文/摘要；不是从旧自动文件冒充新快照。宿主已经删掉、且此前从未进入核心库的内容无法补造。

- 保护文件分类为 `before-deletion`，名称带源库银行、时间与内容摘要派生后缀，位于同一个 `snapshots-v1` 目录。不参与自动轮换，重启/未知写入结果后的重试按精确内容定位并重新读回验证，不重复生成相同保护包。
- 验证成功后调用宿主现有 `window.toastr.warning` 非阻塞提示，明确“检测到正文消失被删除，已自动备份最近核心包”及相对完整文件路径、核心包时间。文本通过 `escapeHtml` 选项转义。同一会话同一文件只提示一次；无该 API 时仅日志回退，面板状态与备份列表仍可查路径。
- 随后归档当前宿主状态，删除楼层的当前正文与当前摘要选择不再出现；依赖被删楼层的高层摘要也从当前选择移出，并在后续同步继续排除。删除证据限定为本绑定已记录的消息映射身份；从未在本绑定出现、已声明生成基线缺失的历史引用仍走原有待审核/人工确认流程，不误判为删除。保留不可变历史摘要/来源证据、其他分支当前正文及受保护文件，不做跨库/跨分支物理 purge。
- 归档提交事务内比较保护前绑定、Head、view、epoch；即便探测“没有减少”，也保留此 CAS 检查，防止探测后并发追加被旧观察误删。还检查宿主观察、聊天数组身份、活动库选择及派生表格代次；检查失败会重试或回滚当前事务，不能把保护过的旧状态当作新状态通行证。
- 整个聊天为空或现有消息身份全部消失时无法可靠区分正常删除、来源尚未就绪或身份丢失，继续拒绝自动对账。关闭自动备份时不增加保护导出；设置读回失败/结果未知不能冒充“已确认关闭”放行删除。
- 写入/读回失败保持核心库旧 Head/正文不变，界面显示删除归档暂缓。相同失败会话按 5/10/20/30 分钟限制后续事件重试，避免渲染通知造成频繁全量导出；“重试删除前保护 / 归档”明确清除此退避并立即重试。未到重试时间的普通刷新不会重复导出。此退避只限制后续宿主事件触发的尝试，没有独立删除重试定时器；没有新事件时需手动重试。普通自动备份仍由原有前台调度器运行。
- 升级前已经对账删除的库无法倒回删除瞬间；如检测到受限的同绑定正向 Head 截短，则另外保护最新已保存、已验证的核心包，显示其原始时间以及可能缺少最后未备份楼层的限制，再使用当前状态继续自动备份。无可用旧包时不会把删除后的包伪装为删除前保护。

性能边界：正常追加/编辑不会全量导出保护包。元数据探测优先复用已验证且 Head 仍匹配的桥接来源视图；冷启动批量读取描述，不逐楼层等待原生磁盘。缺楼层路径不读正文描述。已有保护文件只列文件名并按内容寻址匹配，最多读一个候选文件，不遍历所有历史完整包。真正删除/缩短仍有一次全库导出、JSON 序列化和完整读回校验成本；合成 Node 测试不能证明 Android 不会卡顿。

### 主动删除档案数量减少

“删除聊天档案”指预览中选定的单个分支及其所属记录，不是删除整个 IndexedDB 库。自动备份启用时，明确确认删除之后先导出并验证当前完整包为 `before-archive-deletion`；失败则不进入删除事务。原有删除事务仍逐 store 比对预览完整数据，变化则拒绝，不连带删除父/兄弟档案。成功删除后，只有与这一精确删除计划的结果完全一致的数据，才可保存为 `after-archive-deletion` 新起点。两类文件均不轮换；删除一个测试档不会再因为已知的身份减少永久阻断后续自动备份。

若删除事务成功、随后新起点写入失败，显示“档案删除已完成，新起点待恢复”，保留删除前文件，不谎称删除回滚，也不重新执行旧删除计划。删除最后一个档案时保留保护包、明确提示当前库为空，不创建空库备份或删除旧文件。

对升级前已删掉的档案，提供“保护旧包并接受当前档案（恢复自动备份）”。先显示旧/当前故事、分支、摘要数量和旧包时间，请用户确认这是主动删除；再重新验证同一库最新候选、保护旧完整包、复核当前数据摘要和页面代次，最后接受当前非空库。无旧包/旧包损坏、审批后当前库变化或空库都拒绝；旧包只能恢复其快照时间已保存的内容，不能补造最后未备份资料。恢复保护包是整个核心库恢复，不是单档案撤销，也不恢复宿主聊天文件。默认身份减少守卫未放宽，不把 IndexedDB 丢失等异常当成主动删除。

## 面板读取与暂缓状态（1.4.1）

“读取备份列表”显示读取进度及成功时间，区分尚未读取、已验证 0 份和具体读取错误。读取成功只证明接口和列表结果，不代表创建了备份；已有保存失败或成功状态不会被覆盖。归档错误、绑定冲突、表格待处理或 pending 会立即显示暂缓原因，自动调度、完整导出校验与轮换门禁保持不变。

当前导出和新磁盘备份使用核心包 v13，数据库仍为 DB3；缺失生成基线的显式声明见[摘要来源恢复](20-summary-source-recovery.md)。旧包继续可读，未声明或无法匹配证据的损坏引用仍会阻止备份。

## 1.4.3 校验性能候选

用户报告 1.4.2 启用插件后约 30–40 秒全局卡住，而只关闭自动备份、保持插件启用后稳定。该时间与首次前台备份检查吻合；合成复现进一步发现共享摘要依赖图的重复遍历，以及较早快照链的重复前驱扫描。1.4.3 仅优化这两处校验，不改变上述调度、偏好或轮换规则。手机上还未确认成功写出备份；自动备份先保持关闭，发布更新后先明确手动保存并读回验证，再考虑重新启用。详见[备份校验性能边界](22-backup-validation-performance.md)。

## 一致性与恢复

核心包复用 `exportLibrary()` 的全 store 单次 readonly 事务，之后做领域、正文哈希和包校验。封装再校验来源库、时间及内容摘要。任何读目录失败都不是空目录；设置读取损坏时只关闭自动写入，文件列表和明确恢复仍可使用。

列表可由文件重建，不依赖一个全局索引。会话内只缓存已验证预览信息；选择恢复或固定时重新读全文件并验证。首次列表依次校验文件，避免同时持有全部备份。

恢复需明确确认，先保护当前非空库，再通过 `restoreLibrary(value, false)` 写新库并验证；激活前重新核对页面、选择、原活动库、pending、generation/revision/tableRevision。原库不删除。保护当前库失败需要额外明确同意才能继续。恢复后的普通宿主归档同步会更新当前正文，确认框明确说明；磁盘所选快照保持原样。

保护旧库和切换新库排在桥接既有 source-sync 串行队列中，等待真实写入结束；pending 错误锁存不被当成仍有写入。后续普通同步在退出队列边界后执行，避免自等待。没有引入覆盖所有派生写入的全局写锁：恢复守卫另外检测公开版本变化，原库保留。不得宣称这是所有宿主/插件写入的跨系统事务或全局暂停。

## 大小与隐私

仅核心包；不含知识库文件、字体、向量、API 密钥和宿主聊天文件。文件明文，仅通过本机原生接口落盘。应用卸载、清除 TT 数据或磁盘损坏仍可能删除它们，不替代异机备份。

单文件安全上限 64 MiB（包含封装）；过大时停止写入/轮换并提示手动导出。宿主 API 未提供容量预检，不能声称已验证有足够剩余空间。全库一致导出、JSON 校验仍有整包内存成本，Android 真实峰值内存和低空间错误需现场单独验证。

### TT 原生导出的范围

精确版本的 [data_archive/export.rs](https://github.com/Darkatse/TauriTavern/blob/007abf7f1edfff275cf2a0182bf19179bcef087a/src-tauri/crates/tt-adapter-archive/src/data_archive/export.rs) 中，`run_export_data_archive` 递归遍历整个 `data_root`，排除项只有聊天备份临时文件和文档 `.staging`；因此这些核心包文件会落在完整 ZIP 的 `data/_tauritavern/extension-store/mnemosyne-core-backups/...`。这是固定源码结论，未做用户手机实导出验证。建议完成一次备份并停止写入后，再用 TT 完整数据导出，将 ZIP 另存到自己的安全位置；宿主导出不是本插件各文件的跨文件快照。

单用户 `run_export_user_backup_archive` 的根目录仅为 `data_root/<handle>`（通常 `default-user`），不包含同级 `_tauritavern/extension-store`，不能替代上述完整导出。完整导出可能包含 `secrets.json` 等凭据，应作为敏感个人备份保管，不可公开分享。

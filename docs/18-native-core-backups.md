## 触发、轮换与边界

- 默认关闭，用户在“档案 / 迁移 → 本机磁盘核心包备份”明确启用；启用说明本机明文存储和旧自动文件永久轮换。
- 前台 30 秒稳定等待后检查；正常检查间隔至少 30 分钟，库内容摘要不变不写新文件。导出日期不参与内容摘要。
- 归档 pending/error/conflict/tableError 时延后。前台隐藏或 pagehide 停止新工作，撤销后续轮换；已提交宿主的原生写入不能保证取消。
- 写入失败按 5/10/20/30 分钟退避。仅一个定时器和一次在途检查，不累积每次消息变化的写入队列。
- 每个源库独立银行：固定保留最近 20 份自动文件。文件名包含库哈希、时间、随机 UUID。恢复产生新库，不轮换原库银行。
- 手动保存、新起点、固定副本及恢复前保护文件不自动删除，因此多个库或保护副本会令总数超过 20；面板先展示文件数量，选择单份后显示完整校验得到的大小与计数。没有自动清理历史库、插件目录或用户手动导出文件。
- 只对本功能严格命名、封装归属、源库和完整校验均匹配的自动文件执行轮换。新文件完整读回验证、保留集逐份验证后才删除多余旧自动文件；任何验证或 I/O 异常都保留旧文件并显示警告。
- 全空库或领域无效包仍不写入、不轮换；已确认同步或删除后的有效非空库可直接进入下一次普通备份，不再因数量减少要求保护包或手动接受新起点。
- 旧设置的 5/10 份读取时统一迁移为 20 份，保持原启用状态；下次明确保存设置时写入 20。设置损坏仍停止自动备份，但不阻塞正常删楼、编辑或档案删除。
- 20 个半小时恢复点约对应 10 小时的活跃使用，不保证连续覆盖最近 10 小时。未运行、后台、无变化或保存失败时不补齐；最近一次备份后新增又丢失的数据可能无法恢复。

## 删除与备份解耦（1.4.12）

按用户选择，删除楼层、同 swipe 缩短正文以及明确删除聊天档案均不再创建 `before-deletion`、`before-archive-deletion` 或 `after-archive-deletion` 文件，不弹删除保护通知，也不等待原生备份磁盘、Worker 或备份设置确认。正常归档和档案删除继续使用原事务与当前正文/摘要处理；普通自动备份仍每 30 分钟检查一次。

归档保留独立的来源身份与并发校验：事务内比较绑定、Head、view、epoch 和宿主代次；整个聊天为空或现有消息身份全部消失仍拒绝自动对账，避免把来源未就绪或错误聊天当成删除。明确的档案删除保留预览、依赖和完整事务校验。删除最后一个档案不写空备份、不轮换旧备份。

已有历史删除保护和删除后起点文件保留，仍可查看、校验和恢复，不用作普通备份的阻挡基线。手动保存/导出、固定副本以及用户主动恢复时的恢复前备份不变。恢复整个核心库不等于单档案撤销，也不恢复宿主聊天。

## 面板读取与暂缓状态（1.4.1）

“读取备份列表”显示读取进度及成功时间，区分尚未读取、目录中 0 份和具体读取错误；列出的文件尚未逐份校验。读取成功只证明接口和列表结果，不代表创建了备份；已有保存失败或成功状态不会被覆盖。归档错误、绑定冲突、表格待处理或 pending 会立即显示暂缓原因，自动调度、完整导出校验与轮换门禁保持不变。

当前导出和新磁盘备份使用核心包 v14，数据库仍为 DB3；缺失生成基线的显式声明见[摘要来源恢复](20-summary-source-recovery.md)。旧包继续可读，未声明或无法匹配证据的损坏引用仍会阻止备份。

## 1.4.3 校验性能候选

用户报告 1.4.2 启用插件后约 30–40 秒全局卡住，而只关闭自动备份、保持插件启用后稳定。该时间与首次前台备份检查吻合；合成复现进一步发现共享摘要依赖图的重复遍历，以及较早快照链的重复前驱扫描。1.4.3 仅优化这两处校验，不改变上述调度、偏好或轮换规则。手机上还未确认成功写出备份；自动备份先保持关闭，发布更新后先明确手动保存并读回验证，再考虑重新启用。详见[备份校验性能边界](22-backup-validation-performance.md)。

## 一致性与恢复

核心包复用 `exportLibrary()` 的全 store 单次 readonly 事务，之后做领域、正文哈希和包校验。封装再校验来源库、时间及内容摘要。任何读目录失败都不是空目录；设置读取损坏时只关闭自动写入，文件列表和明确恢复仍可使用。

1.4.13 起，列表只枚举文件名，立即展示保存时间、类别与库分组，不扫描所有核心包。另在原生命名空间的 `preview-hints-v1` JSON 表中保存最多 256 条可丢弃的展示元数据，异步补充列表；无缓存的旧文件、缓存缺失或损坏时仍列出文件，不为建立缓存全量读取旧包。缓存标为待校验，不代表原文件当前可恢复，也不参与轮换或恢复判断。

选择某份备份后，仅在 Worker 中读取并完整校验该文件；改选或关闭页面后丢弃过期结果。Worker 不可用时明确保留未验证状态，不回退到主线程做整包解析；只影响磁盘面板的详情/恢复/固定，原有手动核心包文件导入不受影响，但该入口不直接接受磁盘备份外层封装。恢复/固定按钮只接受此次完整校验得到的详情，并仍在操作时重新读文件严格校验；轮换继续独立验证新文件、保留集和待删除文件，不使用展示缓存。

恢复需明确确认，先保护当前非空库，再通过 `restoreLibrary(value, false)` 写新库并验证；激活前重新核对页面、选择、原活动库、pending、generation/revision/tableRevision。原库不删除。保护当前库失败需要额外明确同意才能继续。恢复后的普通宿主归档同步会更新当前正文，确认框明确说明；磁盘所选快照保持原样。

保护旧库和切换新库排在桥接既有 source-sync 串行队列中，等待真实写入结束；pending 错误锁存不被当成仍有写入。后续普通同步在退出队列边界后执行，避免自等待。没有引入覆盖所有派生写入的全局写锁：恢复守卫另外检测公开版本变化，原库保留。不得宣称这是所有宿主/插件写入的跨系统事务或全局暂停。

## 大小与隐私

仅核心包；不含知识库文件、字体、向量、API 密钥和宿主聊天文件。文件明文，仅通过本机原生接口落盘。应用卸载、清除 TT 数据或磁盘损坏仍可能删除它们，不替代异机备份。

单文件安全上限 64 MiB（包含封装）；过大时停止写入/轮换并提示手动导出。宿主 API 未提供容量预检，不能声称已验证有足够剩余空间。全库一致导出、JSON 校验仍有整包内存成本，Android 真实峰值内存和低空间错误需现场单独验证。

### TT 原生导出的范围

精确版本的 [data_archive/export.rs](https://github.com/Darkatse/TauriTavern/blob/007abf7f1edfff275cf2a0182bf19179bcef087a/src-tauri/crates/tt-adapter-archive/src/data_archive/export.rs) 中，`run_export_data_archive` 递归遍历整个 `data_root`，排除项只有聊天备份临时文件和文档 `.staging`；因此这些核心包文件会落在完整 ZIP 的 `data/_tauritavern/extension-store/mnemosyne-core-backups/...`。这是固定源码结论，未做用户手机实导出验证。建议完成一次备份并停止写入后，再用 TT 完整数据导出，将 ZIP 另存到自己的安全位置；宿主导出不是本插件各文件的跨文件快照。

单用户 `run_export_user_backup_archive` 的根目录仅为 `data_root/<handle>`（通常 `default-user`），不包含同级 `_tauritavern/extension-store`，不能替代上述完整导出。完整导出可能包含 `secrets.json` 等凭据，应作为敏感个人备份保管，不可公开分享。

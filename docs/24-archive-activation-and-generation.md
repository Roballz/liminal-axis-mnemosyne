# v1.4.46 档案重开、继承审核与生成调度

## 分支继承的审核证明

继承只复制父分支在分叉点有效的摘要、总结和对应证据。父分支的角色来源修复可能只涉及摘要的覆盖范围，不一定出现在显式输入列表中；两者均须核对。符合父分支明确修复配对的内容，复制为子分支摘要上的具体来源审核记录，不把父分支全部修复权限授给子分支。

旧版人工审核可能只绑定快照。宿主首次保存继承聊天时，可能把选中回复的 swipe 编号从旧值归零；即使消息身份、正文来源版本和文字完全相同，也会产生新快照。继承时，对于父分支完整快照中已人工确认、没有缺失来源声明、消息身份与顺序可严格对应的旧审核，固定其确切来源、连续覆盖范围及依赖版本，使单纯编号归一化不撤销原审核。生成附注的旧自动审核不使用这项转换。

真正修改正文、替换消息身份、改变相关依赖或缺少来源证明时，仍按原规则进入待审核。不能根据相同楼号或相似文字推断两份来源相同；父分支数据保持独立。

此修复作用于新的继承操作，既有子分支不执行批量自动批准。已待审核的内容，应使用「加载待审核项（只读）」及「查看来源差异」核对；确认原意仍准确后，使用原有审核入口保留，或更新受影响摘要。

## 未变化聊天的只读载入

关闭应用后的缓存丢失、切换聊天后的重新载入是正常过程。未变化的档案不需要为此重新保存整份宿主聊天、重放归档写入及执行历史回收。39 MB 是包体大小，不能单凭它判定 40 秒耗时是否合理。

冷载入先检查宿主已成功归档的回执，再在一个只读事务中核对当前绑定、档案头、消息键、swipe、正文、摘要选择及摘要指纹。回执只是尝试只读路径的提示；不能独立提供有效性证明。当前正文、摘要及共享载荷均实际读取并校验，之后继续执行原有来源审核与派生事件、表格投影。

完全一致时显示「正在读取档案」，省去宿主聊天和元数据保存、canonical 写入及回收扫描。发现正文、角色、消息身份、摘要或基线变化时，回到原有「正在归档」流程。对宿主明确声明的独立生成基线，只做去重的键存在性检查；缺失时交回原有修复流程，不枚举历史正文或摘要。尚未保存的身份、新分支首次同步、缺失来源恢复仍走正常归档。描述符声称一致而正文或摘要载荷不一致时明确报错，不把损坏当成正常缓存命中。

当前事件视图先从小记录中选择最新 epoch，再只解包该版概要与引用。查看事件历史和历史分叉视图仍读取所需的全部版本，排序与同 epoch 的选择规则保持一致。旧式内嵌数据的小记录本身仍可能包含文字；此优化不等于所有旧格式都只读取一段文字。

重开仍需验证当前资料；本版没有宣称恒定耗时或手机秒开。操作次数回归证明去掉了重复写入和历史概要解包，但不等于 Android / 原生 TauriTavern 的实测延迟。

## 事件自动更新不依赖页面打开

摘要引擎、人工事件操作或归档忙碌期间，保存最新一次有效通知，空闲后执行。多个通知合并成一个后续任务，不启动轮询，不为每个通知重复归档。事件开关和间隔设置继续生效；来源异常或需要人工审核的链仍不会自动越过审核。

任务只在开始时取得一份有效正文和摘要视图。每条事件提交前复核分支及来源，任务完成后统一刷新一次派生缓存；已经成功保存的链在后续停止或错误时也可发布。完成发布不再等待插件页面挂载。

任务自身的初始同步已包含在本次输入中，自身最终发布也只对确切的作用域、代次、活动库和 revision 去重。异步读取缓存期间新来的摘要通知不会被忽略。切聊天、换库、停用、显式停止和卸载会撤销不再有效的工作；旧聊天结果不能用于当前聊天。

## swipe 的 Query 历史

swipe 新回复尚未生成时，不能把其暂态末楼存成正式档案，但前面的有效历史摘要仍可作为查询上下文。生成准备现在先获取本次 swipe 已验证的只读历史权限，再进入向量召回中的 LLM Query。最终回复注入复用同一份权限，不在模型请求返回后为另一次生成重新授权。

LLM Query 可以使用有效的逐楼摘要和高层总结。旧末楼、包含旧末楼的高层总结、私有或排除召回的摘要、待审核项、已改变的前缀和未经验证的冷缓存继续排除。没有足够证明时不补造历史；这也不使整个暂态聊天变成「已归档」。

normal / regenerate 保持原有语义。该调整没有新增模型请求；swipe 的历史核验只做一次，查询结束后的注入刷新使用既有权限。

## 数据与验证边界

核心包保持 v18，IndexedDB 保持 v6，无格式迁移。本次改动不执行历史清理或私人数据恢复。自动化验收使用合成消息、fake IndexedDB、真实提示构造及模拟模型传输；未访问用户核心包、真实模型服务或手机。

实现与验证结果见[本轮回执](../notes/v1.4.46-archive-and-generation-review.md)。

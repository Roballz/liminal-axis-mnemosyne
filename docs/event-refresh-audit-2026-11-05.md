## 刷新入口

| 入口 | 流程与结论 |
| --- | --- |
| 单楼、批量摘要提交 | engine 写入叶子、来源与表格结果 → recomputeDerived → derivedMeta.rev 监听 → scheduleDaily → 串行归档 → 生成标签转正式关联 → 发布共享投影。无需打开事件页。 |

| 召回、生成准备、向量索引、人工审核/恢复等显式入口 | syncDaily 串行校验当前档案；保留数据库和来源检查，不应用自动通知的跳过规则。 |

## 根因与改动

共享注入/事件投影原为普通变量。失效时 generation 能使卡片读到 null，但热缓存恢复若未改变事件数据，就不递增 revision，已挂载卡片不会感知恢复。旧代码的回归反例中，直接读取已非 null，卡片 computed 仍为 null。

将投影容器改为 shallowRef，使失效、恢复、发布都可被感知，不深度代理正文、Map 或事件历史。热刷新先发布投影再通知 revision 消费者。未改变来源验证、归档失败或切换聊天时的失效规则。

自动宿主通知增加已同步判断；仅在 pending=false、活动库代次一致、当前 host 匹配且发布缓存就是已归档缓存时跳过。定时器执行前再次判断，避免显式同步已完成后仍重复读取。正在归档时的通知仍合并；完成后无变化不再补跑，真实变化和失败重试仍保留。显式 syncDaily 不跳过数据库检查。

## 后续：读取次数与超时核查

用户后续未再遇到重复主键行，并提出可能存在空格或标点差异；本次不将重复主键作为已确认故障，也不改变主键比较规则。检查基于 `e34a286`，仅调整三处测试及本文档。

- 表格读取：旧测试的辅助函数在写入前后各读一次行列表，插件事务内另读一次用于主键查重。第三次不是缺口处理导致的重复刷新。改为直接测量 applyRows：新增时同表只扫描一次；按 row_id 更新普通列时不扫描整表；两者都不读取表历史或全表定义。事务外的旧列表不能替代事务内唯一性检查。
- 审核时序：生产组件先 await nextTick，再 setTimeout(0) 让出线程显示忙碌状态。测试固定等待 5 ms，在并发负载下可能先于组件定时器完成。改用受控定时器，先排空 Vue 更新再执行定时任务，同时验证忙碌提示先出现、双击仍只提交一次；保留生产组件的让出线程行为。
- 千条来源测试：分段测量（本机 Node/fake IndexedDB，非手机）100/500/1000 条的基础数据创建分别约 204/477/586 ms，旧基线构造约 70/670/2117 ms，statuses 检查约 17/111/114 ms。原 5 秒限制包含全部数据准备。将准备移到独立 beforeAll（15 秒上限），被测来源检查保留默认 5 秒限制及块访问次数上限，未放宽生产算法的断言。

这些证据未显示需要调整生产实现。本次不修改数据库、UI 或 dist/index.js；测试改动可独立回退。

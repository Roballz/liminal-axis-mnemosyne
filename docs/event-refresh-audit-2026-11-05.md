基线：`e351874`，分支 `work/daily-memory-mvp-baibai`。状态：implemented_unverified；尚未在 Android TT 实机验证。

## 刷新入口

| 入口 | 流程与结论 |
| --- | --- |
| 单楼、批量摘要提交 | engine 写入叶子、来源与表格结果 → recomputeDerived → derivedMeta.rev 监听 → scheduleDaily → 串行归档 → 生成标签转正式关联 → 发布共享投影。无需打开事件页。 |
| 聊天渲染、正文编辑、swipe、删除、生成结束、切换聊天 | bindDaily 监听宿主事件；历史渲染先合并通知，流式片段保留完成性保护，内容变化撤销旧投影，再请求自动归档。 |
| 楼层摘要卡片 | FloorEventAction → membershipBadges → currentMembershipHints。只读共享投影，不为每张卡单独查询数据库。 |
| 打开事件页、手动刷新、事件编辑/删除/解除关联、批量或 AI 更新完成 | 页面 refresh → syncDaily → 复用 syncedEventProjection，按需读取问题详情。页面已有 loading/busy 队列和 capturedRevision 去重，保留。 |
| 关联编辑器、摘要标签编辑、自定义表写入/补表 | 提交后 refreshDailyTables → refreshCachedProjection，只更新变化的投影，不重新归档正文。 |
| 召回、生成准备、向量索引、人工审核/恢复等显式入口 | syncDaily 串行校验当前档案；保留数据库和来源检查，不应用自动通知的跳过规则。 |

## 根因与改动

共享注入/事件投影原为普通变量。失效时 generation 能使卡片读到 null，但热缓存恢复若未改变事件数据，就不递增 revision，已挂载卡片不会感知恢复。旧代码的回归反例中，直接读取已非 null，卡片 computed 仍为 null。

将投影容器改为 shallowRef，使失效、恢复、发布都可被感知，不深度代理正文、Map 或事件历史。热刷新先发布投影再通知 revision 消费者。未改变来源验证、归档失败或切换聊天时的失效规则。

自动宿主通知增加已同步判断；仅在 pending=false、活动库代次一致、当前 host 匹配且发布缓存就是已归档缓存时跳过。定时器执行前再次判断，避免显式同步已完成后仍重复读取。正在归档时的通知仍合并；完成后无变化不再补跑，真实变化和失败重试仍保留。显式 syncDaily 不跳过数据库检查。

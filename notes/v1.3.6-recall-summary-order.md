# 1.3.6 连续回合召回与自动摘要时序

基线 `fa84243`（1.3.5），分支 `work/daily-memory-mvp-baibai`。状态为 implemented_unverified：代码和合成环境验证完成，实际手机宿主仍待用户复核。

## 问题与修复

用户报告第一轮成功，第二轮已有融合候选但重排分档为 0，并提示聊天/记忆/设置变化导致取消。该提示来自召回失效处理，不是人物/事件筛选报错。

源码中存在两条确定的触发路径：

1. 新消息启动上一条回复的自动摘要，同时开始召回。摘要保存推进档案版本，清空注入并取消在途召回。现在召回先等待已启动的自动摘要及隐藏/注入收尾，Vue 派生通知落定后，再捕获档案、设置和候选版本并发起 Query。等待阶段只接纳同一聊天、同一输入、同一向量设置的记忆更新；切聊天、新输入、设置变化仍取消。进入实际召回之后，原有版本校验和取消规则保留。
2. `derivedMeta.rev`、宿主事件可能在内容未变化时重复通知。原 `scheduleDaily` 无条件推进 generation、清空缓存并取消召回。现在先核对宿主内容版本；重复通知仅安排同步，不使有效召回失效。显式 `invalidateDaily` 仍能强制失效；归档自身补写消息 ID 纳入观察基线。

取消状态增加具体来源及取消时所处阶段。人物/事件筛选、RRF 排序、各路额度及重排阈值未改。没有修改数据库结构、清理索引、迁移或删除用户档案。无付费模型请求。

## 原因与改动

恢复的祖先核心包不包含宿主较新摘要所引用的生成快照；继承原先会先提交带缺失引用的摘要，再在状态投影时抛出“摘要基线缺失”。因此界面计数 0 并不能证明库为空。该引用接入路径在 1.3.15 已存在，不能把来源缺失直接归因于 1.4.0 的当前正文策略。此结论来自源码和合成重现，不声称已读取用户故障库。

同步现在只对当前分支、与宿主摘要 ID / 基线 / 输入引用 / 覆盖范围精确对应的缺失来源增加版本化 `sourceRecovery` 声明。包含此前已提交的匹配选中和未选中修订；保留摘要、ID、家族、原始生成声明与父档案，不补造快照。宿主证据按 ID 索引，历史核查只读取摘要元数据及被引用的快照，不扫描全部历史正文。

此类摘要持续待人工核对，不进入有效召回或事件生成，旧兼容/旁注回执也不能批准它。逐条“核对并手动确认”可保留原摘要文字，保存另建明确人工确认版本；不调用模型，后续来源变化仍重新失效。高层依赖与事件需要另行审核，批量普通保留不越过这一门禁。

核心包升为 v13，允许严格的缺失来源声明，旧 v1–12 仍可导入；DB3 不变，不增加对象存储。声明不豁免故事、身份、当前正文、事件、依赖或其他引用校验。无法与当前宿主证据匹配的历史坏修订仍严格阻止完整导出，需要另行有证据的定向处理。

备份面板显示列表读取中、成功时间、空列表及具体失败，初始数量未知；立即显示归档错误 / 绑定冲突 / 表格待处理 / pending 的暂缓原因。读取不冒充备份写入，不覆盖既有备份错误或成功状态，重复点击和关闭后的迟到结果受保护。

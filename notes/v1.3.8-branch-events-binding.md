# 1.3.8 分支事件继承与已有绑定修复

基线：work/daily-memory-mvp-baibai / 0fb1004（1.3.7）。状态：implemented_unverified；真实手机/宿主现场仍待用户复核。

## 问题与实现

- 旧 forkBranch 明确创建空摘要视图且没有复制事件，页面也写明不复制。这次显式继承在同一事务中复制固定前缀内的有效摘要、事件链、概要、最新进展、关联、追加进展、归档标记；重新分配分支内身份，保存后父子修改互不影响。较早截止只取可验证的历史事件版本，不能将后期概要裁剪后冒充早期概要。
- 保留已有手工审核以及已确认的精确隐藏角色修复的适用性；不将待审核、私有、禁用或截止之外的来源自动批准。父分支变更与宿主切换会阻止或回滚分叉。
- 绑定冲突时，同 scope 的有效数据库绑定原先被接回列表排除，继承又会报“目标聊天已绑定”。接回专用列表现在包含当前绑定，预览仍核对完整消息身份和正文；同绑定修复不将自身 detach、不新建空档案、不删除事件和表。
- 缓存复用新增聊天元数据 branch 校验，避免元数据已改变却复用旧分支缓存。
- 现场绑定不一致的最初触发因素未复现，不能断言用户曾改名或数据已丢失；本次有合成反例证明并修复恢复死角。

## 数据范围

不升级数据库 schema；复用原有核心包结构并验证导出恢复。只在明确新建继承分支时复制事件，不批量改写既有子分支。自定义表和批处理回执不在本次继承范围内，旧事件整理处理进度不会自动变为子分支的已完成进度。已有摘要引用仍遵守有效性过滤。

异常档案恢复：聊天改名 / 接回已有档案 → 查找原档案 → 选择“当前聊天已绑定，可修复关联” → 预览接回 → 确认是同一聊天。

# 1.3.11 事件继承、历史回退与手动重新继承

基线为远端 work/daily-memory-mvp-baibai 的 f0438f3（1.3.10），施工分支 fix/fork-event-projection，起始工作树干净。状态 implemented_unverified；实际 TT / Android UI 待用户复核。

## 根因及修复

- 历史事件视图原先比较保存事件时的整个聊天前缀。事件实际未使用的楼层发生变化，也会排除全部旧关联、清空概要/最新进展，或让归档链整条不可见。改为校验事件记录截止点、所属分支和实际来源摘要；无来源声明的空记录仍严格校验完整前缀。后期记录不会因来源较早就被倒填到旧楼层。
- 关联是摘要家族的关系；正文/概要仍依赖具体版本。已确认新版摘要的旧关联现在能正确对应当前版本，不自动批准旧概要。标题、概要、最新进展一起选择可验证的历史版本，不截取后期概要冒充早期剧情。
- 旧继承只复制当前投影，并把所有记录截止点设为分叉点。现在复制合法历史元信息、关联/解除关联、追加进展，保留各自截止点及版本顺序，分配子分支 ID。归档链同样继承；后续对子分支再次从较早楼层分叉能使用早期版本。没有可验证早期版本仍跳过。
- 在用户包的隔离完整分叉/导出验证中发现原有审核依赖身份问题：保留高层摘要后，旧依赖仍指向父摘要家族，但审核依赖已映射到子家族。现在把所需未选中旧依赖一起复制到对应子家族，保留旧内容及来源；显式审核保留优先于角色兼容确认。不是把旧版本直接批准成当前版本。

## 手动重新继承

保留“刷新”原用途，子分支事件页新增“重新继承父事件链”。读取保存的父快照和截止点，先只读预览新增、补齐/更新、跳过及原因，确认后在一个事务里写入。

新版事件保存来源凭据及投影摘要校验值，重复执行同一结果不重复导入。只替换未在子分支编辑的继承事件，保留事件链 ID；替换其导入记录并复制父档案的合法历史。子分支自己编辑过概要、关联、标题或归档状态的事件不覆盖。来源摘要身份、内容、来源及依赖无法对应时跳过，不补写摘要。父档案、源正文、摘要、绑定不变，不调用模型，不自动扩大分叉范围，不删除父档案已不存在的子事件。

旧版没有继承凭据，只有创建信息匹配、单一初始版本及关联版本均为旧版继承初始 epoch 的记录才允许修复；多候选/同名不明不覆盖。确认时复核父子分支及事件链状态，切聊天、来源变化或中途撤销都使事务回滚。

核心包导出 v10，继续读取 v1～v9；校验继承凭据字段、父分支、版本范围及摘要格式。没有升级 IndexedDB 物理 store/schema。旧版扩展不支持 v10 包，回退需兼容版本或更新前备份；代码回退不会自动撤销已确认的重新继承。

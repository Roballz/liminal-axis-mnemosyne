## 行为与实现

1. `commitSummaryTables()` 的原生事务完成后立即发布本批表 ID、起止楼号和已完成批数，早于后续投影刷新。弹窗局部更新 `last = max(last, end)`、下一起点 `end + 1`，不重新扫描全部回执。未确认、保存失败、取消不会提前推进。手动历史重补沿本次选定范围前进，历史最后确认不倒退，也不会跳到更晚的历史确认点。
2. 一次任务复用 `syncDaily()` 已验证的正文快照与 `refs/sources`，每批仅创建小型 view 包装。聊天、generation、库 Promise 身份、库激活代次、head/view 及写入 CAS 继续检查。表提交只修改当批包装，不污染 bridge 的共享缓存。
3. 每批重新读取当前分支、当前摘要选择及所选摘要元数据，再检查来源有效性。摘要来源修复标记可被另一连接原地修改且不推进 epoch，不能把正文复用扩大为永久复用旧摘要审核状态。正文或角色变化沿既有不可变 revision/head 处理。
4. 当前批次仍按用户指定楼数与范围发送一次，附所选表的全部有效可见行；不附此前批次正文。超预算在 sender 之前退出，本批不发送、不截断、不自动缩批，保留已提交进度及原每批楼数。
5. 独立补表使用统一完整材料检查，上限 `270000`。正文 JSON、表定义/有效可见行、填写指令及分隔文字三项之和等于完整 system/user 长度。普通摘要的 `summaryTablesPrompt()` 默认 `96000` 保留；独立补表由外层统一检查，避免内层旧上限提前报错而丢失明细。
6. 大表格式预览第一次展开才序列化，在当前审阅内缓存；保存 busy、错误、预算变化、折叠重开复用字符串。结束审阅和新批次清除缓存，旧表对象的延迟 toggle 不会污染新审阅。

## 270,000 字符的依据与限制

计量沿用 JS `String.length`（UTF-16 代码单元）：通常汉字、ASCII 字母/数字和标点各计 1，代理对字符计 2，组合 emoji 可更多。预算覆盖整个模型输入，不能理解成只容纳 27 万个正文汉字。

2026-10-28 检索的官方资料：

- [DeepSeek 模型说明](https://api-docs.deepseek.com/quick_start/pricing/)：`deepseek-flash` 当前对应 `DeepSeek-V4.1-Flash-1017`。
- [DeepSeek token 使用说明](https://api-docs.deepseek.com/quick_start/token_usage/)：中文粗估 0.6 token/字，因此 180,000 tokens 粗算为 300,000 汉字；官方明确提示应以返回 usage 为准。
- [Gemini token 说明](https://ai.google.dev/gemini-api/docs/tokens)：通用“每 token 约 4 字符”的例子包含英文词数，不能直接套为 4 个汉字；精确计数需要对应模型的 countTokens。
- [Google 官方 SDK 本地 tokenizer 映射](https://github.com/googleapis/python-genai/blob/main/google/genai/_local_tokenizer_loader.py)：2.0/2.5 Flash、3 Flash preview 使用 gemma3；3.5 Flash、3.1 Flash Lite 使用 gemma4。本次未验证该映射之外的全部 Flash 版本。

离线只使用官方公开 tokenizer，没有下载模型权重、调用模型 API 或使用用户 RP 正文：

- [DeepSeek tokenizer 固定 revision](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/tree/1bae0e1088993b9b82de08f59de5be5a34e42170)
- [Google Gemma3 tokenizer 固定文件](https://raw.githubusercontent.com/google/gemma_pytorch/014acb7ac4563a5f77c76d7ff98f31b568c16508/tokenizer/gemma3_cleaned_262144_v2.spiece.model)，SHA256 `1299c11d7cf632ef3b4e11937501358ada021bbdf7c47638d13c0ee982f2e79c`
- [Google Gemma4 tokenizer 文件](https://huggingface.co/google/gemma-4-E4B-it/blob/main/tokenizer.json)，SHA256 `cc8d3a0ce36466ccc1278bf987df5f71db1719b9ca6b4118264f45cb627bfe0f`

合成文本的少量离线计数（包含标点，不包含服务端聊天模板包装）：

| 材料 | UTF-16 字符 | DeepSeek tokens | Gemini 官方本地 tokenizer tokens |
| --- | ---: | ---: | ---: |
| 简体叙事 | 979 | 586 | 695 |
| 自然对白 | 343 | 208 | 247 |
| 档案摘要 | 244 | 167 | 180 |
| 三项合计 | 1566 | 961 | 1122 |
| 繁体叙事 | 170 | 131 | 140 |
| 生僻字压力样本 | 107 | 128 | 118 |
| 补表 JSON 混合样本 | 2847 | 1427 | 1647 |

Gemma3 与 Gemma4 在这些样本中的计数相同。前三项为约 0.614 与 0.716 token/字符，两侧平均约 0.665；`180000 / 0.665 ≈ 270648`，按用户要求取整为 270,000。按同一组样本外推，DeepSeek 约 166,000 tokens，Gemini 约 193,000 tokens。这是以 180,000 为中心的折中，不是两家都小于 180,000 的保证；繁体、生僻字、数字/JSON 比重和模板都影响结果。未对私人长篇 RP 或全部线上版本做实测，也不构成统计置信区间。

输入字符预算不修改 API 渠道的输出 token 上限，不新增联网分词或付费预检请求。

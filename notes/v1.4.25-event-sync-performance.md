# v1.4.25：事件与同步性能第一批

基线：`59908dd550265bd3f4ff7e2ae31ec2016aa673cb`，分支 `work/daily-memory-mvp-baibai`。

## 问题与实现

一次事件关联修改原本仍反复序列化整段聊天、哈希已完成回复、校验全部摘要，并读取无关表格和事件历史。本批处理性能审计中的 F01/F02/F03/F05–F09，不扩展到普通正文归档、派生状态重放、召回和备份的后续批次。

- 宿主版本保持原 JSON 格式；逐次精确对比不可变快照，未变时复用字符串。覆盖同长正文编辑、嵌套原地修改、键顺序、数组空洞；Date、toJSON、访问器等未知形态走原序列化路径。
- 已完成回复按消息、正文、swipe、回执完整值及宿主作用域缓存成功的指纹验证；每次仍检查实时生成、停止、pending/aborted 和未产生的 swipe。异步变化不得发布缓存证明。
- 仅成功提交后记录本连接的有限变更证据，最多64笔、512项分支/事件证据；单笔事件超过128条不允许增量复用。未观察到的连接变化、日志缺口、未知写入、来源/摘要/审核变化均退回完整校验。不是跨标签页的全局版本，不写入持久协议。
- 事件/表格变化按实际依赖刷新。同次有效性结果共享；已证明仅改事件时不读表、不重建正文/摘要投影，也不增加 tableRevision。读后复核分支、宿主、库选择和本连接变更版本。
- 当前事件只缓存一个分支的最新元信息、按摘要 family 折叠的最新关联状态及必要追加进展。连续已知变更增量更新；历史详情和历史截止点仍走原读取路径。
- 每次轻读事件链的组织标记，因此归档操作继续不推进事实 epoch，也能反映其他连接的归档变化。未变投影保持对象稳定，避免额外 revision 通知和页面循环。
- 事件页复用本次同步确认有效的投影，包括其他入口已提前发布的结果。保留切聊天、切库、卸载和末端来源复核。
- 单目标加入只读目标链；新建链不读旧事件。收窄事件相关事务；概要保存复用当前摘要 Map，缺失旧版本在一个事务内读取。
- 库激活立即撤销旧库缓存 getter；进展并列时保持 IDB 主键顺序，保证增量和冷读结果一致。

## 原因与实现边界

原有自动备份在身份计数或当前分支消息减少时拒绝继续；若在归档删除之后才备份，旧正文已不在当前核心库，仅能保护此前保存的旧包。候选将可确认的宿主正文删除 / 同 swipe 缩短保护前移：在 source-sync 队列中导出当前已归档完整核心包，磁盘写入与完整读回成功后才允许破坏性对账。

- `before-deletion` 文件按内容寻址去重，永久排除于自动轮换；提示显示相对完整路径与核心包时间，宿主原生 toast 文本转义
- 事务比较绑定、Head、view、epoch，另检查当前宿主观察、聊天数组、活动库与表格代次；检测不减少的路径同样保留 CAS
- 失败保留旧 Head / 正文。后续宿主事件触发重试受 5/10/20/30 分钟退避限制；没有独立删除重试定时器，面板明确重试可清除退避
- 正常受保护删除后继续原有自动备份调度；全空 / 全量身份丢失仍保守拒绝
- 删除楼层及依赖其来源的高层摘要从当前分支选择移出，后续同步持续排除；仅把当前绑定映射中已知、但当前 Head 不再包含的身份认作已删除，未知历史缺失基线证据仍保留原人工恢复审核入口；不可变历史与其他分支保持
- 升级前已经对账删除只可能保护最新已保存、已验证旧包，显示旧包原始时间，不声称恢复最后未备份楼层
- 摘要卡显示全部正式链名，文字左对齐，单独图标位于右侧上方星标 / 搜索操作中点下方；空关联灰色斜体，加载 / 未知明确区分
- 普通追加不导出保护包；冷启动批量读取描述，保护文件只匹配内容地址后读取一个候选，摘要依赖检查共享缓存，保留既有核心包 DAG / 历史前驱性能修复
- DB3 / 核心包 v13、依赖与锁文件不变，不调用模型或远程服务

## 明确删除档案与旧事故恢复

- 自动备份开启时，明确删除档案先在全 store 只读事务复核原预览包，写入并读回 `before-archive-deletion` 保护，再沿原全 store CAS 执行删除，之后保存严格匹配删除计划结果的 `after-archive-deletion` 起点
- 删除前失败不执行删除；删除已提交但起点写入失败时如实提示已删除，不要求重复删除；最后一个档案删除后保留保护包，空库继续拒绝自动写入 / 轮换
- 旧事故手动恢复路径：档案页 → “本机磁盘核心包备份” → “保护旧包并接受当前档案（恢复自动备份）…”；核对旧包时间与故事 / 分支 / 摘要数量减少，明确确认后先保护旧包，再接受当前非空库作为起点
- 此按钮不会恢复宿主聊天或补造尚未备份数据；若需要旧档案，应选择整核心包恢复。保护失败不接受新起点，旧包 / 当前数据变化需重新预览

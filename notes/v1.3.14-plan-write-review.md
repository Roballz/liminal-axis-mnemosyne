# 1.3.14：计划／悬念写入排查与停用摘要关联

基线：`029db62`（1.3.13），目标分支：`work/daily-memory-mvp-baibai`。状态：`implemented_unverified`；源码与合成数据验证已完成，真实宿主/手机和供应商输出待现场确认。

## 源码结论与现场边界

- 单楼自动摘要、单楼补摘和重摘的 `plans.add/update/resolve` 管线可用。内容、当前进展、仍待解决各限 100 字，超长会截取，不因超长拒绝整条。`update` 原本只修改当前进展和仍待解决，内容保留初始描述。
- 旧实现会把 `tags.planIds` 单独折算为关联楼层，即使模型完全没有输出 `plans.update`。这能解释“全都多了 #559 关联而进展不变”的机制，但没有用户那次模型原始返回，不能断言其现场具体原因。
- 默认新增准入严格，绝大多数楼层不新增；已有事项的真实进展应更新。此次保留准入门槛，明确“默认不新增”只针对 add，不限制 update/resolve。
- 自定义摘要模板缺少计划宏时，原本没有兜底目录，模型可能拿不到可更新编号；此次补齐未了结和近期已了结目录。多楼批量补摘原本不写计划变更，此次保持。

## 改动

- 暂停计划／悬念与摘要的关联：不生成、不接受模型关联，不再从历史标签折算 `relatedLeafIds`；隐藏关联楼层、摘要关联展示和选择框。召回忽略旧计划关联的加分和附加文本，人物/公开与事件链关联保持。
- 保留历史原始 `planIds`/旧字段的读取兼容，不批量清洗存档。计划的稳定编号仍供自身 update/resolve 使用，不是摘要关联功能。
- 明确 JSON 根字段 plans、更新字段和有效编号；过滤只有 id、没有任何进展字段的空更新，防止其推进进展时间。自定义模板漏宏时补齐目录。
- 摘要页临时显示最近一次成功单楼摘要的处理计数：未返回、空指令、有效写入、无效过滤、格式问题和超长截取。以宿主 scope 与当前有效叶子校验归属，不新增持久原文日志，不追溯升级前输出。
- 召回缓存键升级为 `hybrid-v3`，避免复用含旧关联文本的 v2 结果；升级后第一次需重新召回，随后仍复用同轮 swipe/重新生成缓存。无需重建索引。
- package、manifest、安装产物同步到 1.3.14；用户指南加入排查说明。

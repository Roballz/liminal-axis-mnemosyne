# v1.4.46 继承、冷载入、事件调度与 swipe Query 修复

## 范围与基线

- 基线：`work/daily-memory-mvp-baibai`，`04168400b1e88014b32154566d4ff6c93ac50b6d`，v1.4.45。
- 用户确认此前关键词并未消失，从自动备份恢复后重新清理，事件链已基本正常。
- 本轮处理四项新报告：继承后部分摘要/总结进入待审核；重开或切聊天约 40 秒；事件自动刷新依赖打开页面；swipe 的 LLM Query 缺少历史摘要总结。
- 核心包 v18 / IndexedDB v6 不变；没有读取用户真实档案或执行其数据恢复。

## 确认的原因与修复

| 问题 | 合成反例确认的原因 | 修复 |
| --- | --- | --- |
| 继承后待审核 | 覆盖范围中的角色修复未复制；旧人工批准只绑定快照，swipe 编号归一化后失效 | 输入与覆盖分别继承确切证明；符合严格身份和范围条件的旧人工审核在复制时固定来源、覆盖及依赖 |
| 冷载入慢 | 缓存丢失后保存整份未变宿主聊天并重走写入流程；当前事件只用最新版却解包全部历史概要 | 当前观察与档案严格一致时只读载入；当前事件只解包最新概要 |
| 事件等待刷新 | 引擎或人工任务忙时直接丢弃通知；事件提交后未发布新投影 | 保留并合并通知，空闲后继续；结束时统一发布，精确排除自身通知 |
| swipe Query 无历史 | 只读历史权限准备发生在 Query 请求之后 | 在 Query 前准备权限；结束后复用本次权限，禁止转而授权后来一次 swipe |

这些是源码和合成反例确认的缺陷，不能据此断言用户私有档案的每条待审核项或全部 40 秒均出自同一原因。

## 针对性反例与性能检查

- 继承：覆盖范围独有的角色修复分别作用于 L0 和高层总结；旧人工批准随 swipe 2→0 保持有效；真实改文和换身份仍失效；包含导出恢复与父子隔离。
- 冷载入：关闭并重开实际测试库、切到另一聊天再切回；未变化时宿主保存次数和 canonical 写入次数均为 0。离线同长度正文修改仍走正常同步。
- 只读事务：普通和共享存储各含 8 条当前正文、4 条当前摘要及未选历史；正文描述符 8 次、正文载荷 8 次、选中摘要 4 次，单次只读事务；共享 manifest/payload 每份只读一次，不枚举历史正文、摘要或快照。相同长度损坏、基线错配及变化中的守卫均拒绝。
- 事件冷投影：67 个含共享概要的历史版本，当前视图只解包 1 个，历史视图仍解包并展示 67 个；同 epoch 选择不变。修复前当前视图也解包 67 个。
- 事件调度：引擎忙、人工审核忙、连续通知、任务内初始同步、停止/切聊天/卸载；两项异步发布反例覆盖读取期间及发布之后的新通知。修复前后者只发起 1 次而漏掉所需第 2 次；修复后恰好跟进一次，自身发布不循环。
- swipe：检查真实 Query 请求体中逐楼与高层历史，覆盖 normal/regenerate/swipe；私有、禁用、待审核、改变前缀、无已验证缓存、旧末楼和含旧末楼总结继续排除。模型和外部索引 IO 使用模拟，不调用付费服务。
- 首轮全量回归发现 1 项旧库缺失基线兼容性失败（其余 1,660 项通过）：旧记录与宿主指纹一致但缺少恢复标记，新路径绕过了原有补标记流程。现对宿主声明的基线按唯一键检查存在性，缺失即回到原有归档修复；修正后的恢复、确认、冷载入与 bridge 集成集 163 项通过。没有放宽审核或扫描全部历史。

不增加轮询、逐摘要刷新或额外模型调用；事件任务保留一份当前视图并在结束后一次发布。冷载入仍需当前内容校验，未承诺特定手机耗时或帧率。

## 使用边界

- 继承修复作用于新的继承操作；既有子分支不会批量自动批准。先通过只读来源差异核对，再使用现有保留或更新入口。
- 事件自动更新继续受开关、间隔和来源审核限制。此修复处理漏通知与缓存发布，不自动批准有来源问题的概要。
- 未变化冷载入显示「正在读取档案」；实际变化、新身份、未落盘内容或需修复证据仍显示「正在归档」。
- 状态为 `implemented_unverified`：自动化回归通过后仍需用户实际 TauriTavern / Android 档案验收，合成 IO 次数不等于原生耗时。

长期行为说明见[档案重开、继承审核与生成调度](../docs/24-archive-activation-and-generation.md)。

## 实际改动

- 计划／悬念增加短标题、当前进展与仍待解决。副模型逐楼摘要协议支持 `plans.update`，正文真实进展才更新；稳定 ID 和关联叶子随增量回放，保留截止语义。卡片末行显示关联楼层，召回摘要下显示简短事项引用。
- 叶子摘要保存可编辑人物／计划／事件标签；公开开关只接受手工设置并要求理由。模型不能自行公开摘要。标签生成校验目录中的稳定 ID，自动事件相关标签不会修改人工事件成员。
- 事件增加带来源摘要 ID 的最新进展，文字至多 30 字，剧情时间由来源取得。有效的进行中、暂搁事件在计划之后分组常驻；详细事件概要仍留在召回展开中。旧事件在下次概要更新补齐，不批量调用模型。
- Query 保留原 INTENT/Q，另外输出上下文人物及事项 ID。原始融合排名给全部已取候选计算 RRF，原 Top N 送 rerank；只对独立 RRF 摘要通路排序偏好，其他候选留作补位，BM25／向量通路及升原文门槛不变。人物或公开、向量高分例外、BM25 前 N 名例外决定优先组，事项相关性只作有上限且不叠加的正向加分。
- 默认高相关例外 0.9、BM25 前 5 名例外、事项加分 15%，均有设置入口。调试记录保留原始分、偏好分及理由。元数据格式错误不破坏普通查询，既有分支、截止、权限与迟到结果守卫仍在。
- 只改标签可复用同一叙事依赖，不制造无关待审核；兼容审核仍必须匹配原文精确版本。事件缓存随有效视图和分支 epoch 刷新，异步提交之后重新核对来源状态。
- 核心包升级 v7，兼容导入 v1～v6；新增字段版本化并验证来源、随包导出。聊天计划增量仍按原宿主 chat extra 保存，不改变核心包对 chat-state-delta 的排除声明。无物理库升级、数据清理或自动重标旧摘要。

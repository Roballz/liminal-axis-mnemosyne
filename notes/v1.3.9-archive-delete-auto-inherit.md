# 1.3.9 单档删除与新分支自动继承

基线：work/daily-memory-mvp-baibai / ac6fcf3（1.3.8），干净工作树。用户明确缩小范围：仅删除单个聊天档案，不提供整个故事/全部分支删除。状态 implemented_unverified，真实宿主现场待用户复核。

## 行为

- 档案页新增“手动删除聊天档案”：加载所有本机档案（包括宿主聊天已删除、已脱离绑定的档案），选单个档案、只读预览数量、明确确认后永久删除。宿主聊天不会被删除。
- 有子分支或其他档案仍引用目标数据时拒绝删除。仅删除预览中的分支数据、其绑定/映射与不再需要的源记录；共享父来源保留。提交前复核预览快照，全部删除和暂停标记在同一事务，失败/切换撤销，不存在级联删除入口。
- 保存版本化的 archive-deletions 设置，仅记录暂停建档的聊天 scope，避免删除后后台立刻重建。显式选择新故事、手动继承或接回可解除该 scope 的暂停。删已脱离绑定的误建档案，不暂停同名 scope 当前连接的正确档案。
- 新分支有宿主 main_chat 来源标记、同角色/群组唯一来源、尚无当前绑定时，使用原手动继承路径自动验证完整建议前缀（min(父档案长度, 当前聊天长度)）。不寻找“最长相同文字”或缩短前缀掩盖差异。缺来源、身份/正文不符时仍留手动处理；无宿主分支标记的改名不按相同内容推测分支。
- 成功提示“已成功继承xxx档案”，失败提示“档案继承失败，请手动检查。”。同会话同目标失败不反复弹窗；切聊天后不向另一个聊天发旧结果提示。名称按文本转义。
- 宿主依据为 SillyTavern release/public/scripts/bookmarks.js 的 createBranch：newMetadata.main_chat 来自创建分支时的 sessionName。此为上游接口取证，并非用户安装版现场已验证；不支持该标记的宿主仍走手动入口。

## 数据与兼容性

IndexedDB stores/schema 不变。核心包版本升到 8，仅增加受白名单约束的删除暂停标记，旧版本 1～7 继续可恢复。新包需 1.3.9 或更新版本读取；旧版本不会理解删除暂停标记。后台普通同步增加一次 library_meta 单记录读取，不扫描正文；全档案预览仅由用户按钮触发。

## 验证

- 针对性 archive-deletion + bridge：50/50 通过，随后补充脱离绑定同名档案和较早楼层自动继承反例。
- 最终 npm test：34 文件、480 测试通过；timeRel 810、vector depth 12、memory regression 53 断言通过。
- vue-tsc --noEmit、npm run build、git diff --check 通过；构建保留既有 >500 kB 分包提醒。版本、manifest 缓存参数与 dist 更新到 1.3.9。
- 覆盖单档删除/表与事件清理、无关故事保留、父/兄弟分支隔离、共享来源保护、预览过期/事务中取消回滚、最后一个档案删除、导出恢复、暂停重建与显式重建、自动成功一次提示、正文不符零写入、同名跨角色拒绝、切聊天取消、较早截止。
- 实现：新增 archive-deletion.ts 80 行；bridge 约 96 行新增/26 行调整，页面约 45 行新增，迁移约 9 行新增。测试：新增删除测试 79 行，bridge 约 101 行新增/调整，5 处包版本断言跟进。准确增删以提交 diff 为准。

不对用户真实档案执行删除；代码、合成 IndexedDB 及构建验证不代表手机现场完成。永久删除须用户在页面确认，数据恢复只能依靠删除前的核心包。回退代码不恢复已删除数据，旧版本也不识别暂停标记；回退前保留新版本与核心包。

## 问题及四项修复

人工确认 L0 摘要使用固定基线前缀，保留宿主指纹而清空显式输入来源。旧同步流程依据宿主生成旁注判断要写审核，却读取当前人工确认版本的空输入数组，产生空来源的自动审核。日常状态检查缺少应有来源身份比对，会把空数组当作有效；整库导出较严格，因此所有备份入口被同一历史记录阻断。

1. 自动旁注只为仍具有非空、精确匹配宿主证据的输入来源和覆盖信息生成审核。人工确认前缀摘要不再误入该路径。
2. 备份或导出准备阶段，通过正常主库连接分批检查已有审核。仅对可确认的旧缺陷增加 `disabled: { version: 1, reason: 'empty_generated_sources' }`；保留原记录全部字段，不重写正文、摘要、表格或来源证据。包含非当前档案和未选中的历史摘要。每个受影响分支推进一次 epoch，使跨连接旧视图失效。
3. 日常状态与分支继承检查来源消息身份、覆盖身份和依赖家族；未迁移或已停用的错误审核均不能批准摘要。人工保留、标签等价、角色修复和缺基线恢复继续受各自规则约束。
4. 按库持久保存轻量备份健康信息，导航与折叠标题可见失败和最近成功时间。开关成功或 `too-soon` 不清错；真正保存成功更新日期；当前库和已有基线重新验证后可清错，但不伪造新的备份时间。预备修复失败同样记录；取消或过期任务不污染新库。接通手动重试。

## 数据协议与恢复

- 数据库物理版本仍为 5；核心包升级为 v16，继续读取 v1–v15。
- v16 包含可校验的停用原因及 `review-source-repair-v1` 完成回执。停用仅允许已知空来源自动审核组合；其他字段和全部其他数据继续严格校验。未知错误保留，并报告档案、摘要楼层、审核 ID、来源/覆盖列表及差异数量。
- 原始审核仍在包内。导入导出往返已验证，不通过删记录或补造来源使坏包过关。完成回执中的 disabled 数量只统计成功完成的那次维护调用中新停用的记录，不作为累计修复总数或权限依据。
- 新格式包需使用支持 v16 的插件恢复。旧格式备份保持可读；回退旧运行文件无法识别新增停用字段和回执，不能作为本次数据修复的撤销方法。
- 备份 Worker 与 `exportLibrary()` 仍只读已有数据库。维护在调用者捕获最终备份 guard 之前执行；每批重读比较，过期时回滚当前批，已提交批可在下次安全续处理。
- 备份健康缓存为版本化的显示元数据，每个浏览器最多保存 12 个库、每条错误最多 2048 字符，不参与核心库语义、备份校验或文件轮换。

## 性能验收

- 每批最多游标访问 128 条审核，事务结束后让出事件循环。只读取候选所需摘要和历史清单元数据，不读正文或正文版本表，不使用全表 getAll。
- 同一页按基线聚合锚点，复用历史块消息索引。测试曾捕捉到 128 个锚点重复检查同一 256 条引用产生 16,512 次比较；修正后满足至多 512 次的操作上界。
- 300 条旧回执每条仅访问一次，无正文读取；受影响分支仅写一次。并发调用合并；同连接再次调用不扫描、不写入，新连接读取完成回执后同样跳过扫描。
- 状态审核的历史摘要和依赖按唯一 ID 集中读取，前缀身份比较复用已有块，不为每条审核复制完整正文前缀。
- 历史备份时间提示只枚举一次目录；100 次已有归档变化信号不会重复读取目录或打开任何备份包。没有新增轮询、逐条刷新或主线程整包解析。

## 更新后的预期行为

下一次自动备份、手动保存或导出前，会自动分批处理可确证的旧空来源审核。成功后恢复正常完整校验和备份；重新启动不重复维护。仍有其他异常时，错误会直接显示位置与具体差异，并保留故障日期，便于继续定位。

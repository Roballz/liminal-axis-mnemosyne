# v1.4.16 事件链楼层优先继承回执

基线：`work/daily-memory-mvp-baibai`，`d4f782a3195ce303969cc36590b8a7473f764b9d`（v1.4.15），开工工作树干净。需求是事件按实际关联材料所在楼层继承，而不是因为较晚创建、归档或整理概要就整体遗漏；同时让已有子分支通过事件页“重新继承”补回旧规则漏掉的事件。

## 实现与语义

- 只改 `eventView(..., true)` 的分叉 / 重新继承投影。普通事件页、召回与历史目录的原有投影方式不变；归档标志仍仅控制展示。
- 每个候选事件版本先检查其 `refs`、概要覆盖 `summarized`、最新进展来源，以及该版本 epoch 时的有效关联。每条摘要必须先通过既有 `statuses`，再核对生成来源、coverage、锚点及高层摘要依赖的完整材料楼层。
- 楼层证据不是单个显示序号：关联材料在事件保存快照和目标前缀中的位置、消息 / 来源版本与 swipe 变体必须一致。已有效人工确认的来源继续遵守既有审核结果；不凭旧来源 revision 相异就撤销合法的人工确认。
- 全部材料符合时，不再以较晚保存时的 cutoff 否决。仅批量建立关联、尚未写概要的空链可用当时关联作为证据；任意无来源手写概要不能靠旧楼层关联被倒推为历史事实。
- 材料跨越分叉点、证据缺失 / 非法，或没有可靠来源时，回退原有历史筛选。概要作为整体选择，不删除未来引用后保留可能混入未来的整段文字；存在较早合法版本时使用该版本。
- 解除关联属于用户操作，不是剧情楼层事实，仍按原操作 cutoff 回退。若较晚解除操作尚不适用，该操作之后的元信息也不走楼层捷径，避免保留早期关联却误用被清空的后期概要。
- 所有继承的事件版本、关联历史及进展历史都映射为子分支本地 ID，并将保存范围限制在子分支快照长度内，保证导出 / 恢复及继续向更早位置分叉合法。父记录不改写。

## 已有分支的重新继承

- 复用事件页现有“重新继承”入口和预览 / 应用流程，不新增按钮。预览文字说明可补回较晚创建或整理、此前被旧规则遗漏的事件。
- 仍使用已保存的父分叉快照 / 长度，不跟随父分支最新尾部。已有子分支保留有效来源摘要时，可新增漏掉的父事件，或替换未修改的既有继承事件。
- 子分支来源映射额外核对实际材料的位置、SourceRef 和 swipe 变体；同文不同 swipe 不能仅因摘要文字相同就重新继承。高层依赖继续通过原有映射闭包校验。
- 子分支自行修改、来源摘要缺失 / 改变、身份冲突等仍跳过；预览只读、重复应用幂等、父子变更检查和事务撤销均保留。没有有效父分叉记录或缺少对应摘要时，不猜测重建。

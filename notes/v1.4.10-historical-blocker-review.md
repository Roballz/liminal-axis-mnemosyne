# v1.4.10 历史未确认楼层诊断与定位回执

日期：2026-10-16。基线为已发布 v1.4.9 `470f56ae0281db28301797874e4ddbeead462a61`，分支 `work/daily-memory-mvp-baibai`。本候选未提交 / 推送，发布须另行确认；状态只到 implemented_unverified。

## 原因与范围

完整回复尾部报 API 错误后，当时忽略人工确认，可能留下很多楼之前的未确认收据。复现证明：后来正常追加、再原生保存最新楼层，会把最新楼层记为 edited，但旧楼层仍阻挡整份归档，摘要审核因而仍不可用。v1.4.9 的原生确认支持任意准确楼层，不是仅支持末楼；缺口是错误只给笼统提示，无法找到真正需要核对的旧楼层。

本轮按用户确认补充诊断和定位。没有读取真实聊天、生产日志或备份，没有调用摘要模型，也没有修改 TT 或用户设备。

## 实现

- 归档完成性错误附带首个阻挡楼层、swipe 和原因：仍在生成、swipe 未形成正文、未取得完成确认、停止 / 中断、疑似 API 错误、正文 / swipe 不匹配、未知确认记录。
- `ReplyFinality` 的门禁与只读诊断共用分类，保留 assistant 角色、准确正文哈希、swipe、错误标记、实际处理器与生成候选的原有隔离条件；`edited()` 及真实保存授权没有放宽。
- 摘要编辑弹窗与归档页共用 `ReplyBlockerPanel`，无需先重新继承或反复保存最新楼层。核对准确旧楼层后用其原生勾号保存；未修改正文也可明确保存，不要求人为添删文字。
- 面板先使用已有首个错误；只在用户点击时检查其他楼层。每页最多覆盖 100 个不同楼层（包括 user / system / 跳过项）、最多 10 个发现，替换上一页，最多显示首次项加本页共 11 条。
- 诊断不调用 observe / stamp / candidate / sync，不创建收据、不保存宿主、不解除隔离、不触发模型。页内准确校验仅涉及本页；续页游标使用常量成本的上下文和生命周期代次，不保留或重新校验此前页。连续页是各自检查时的观察，不能当统一有效快照；正式归档仍执行完整门禁。
- 聊天 / 编辑 / swipe / 生成等生命周期变化撤销旧页与跳转；普通后续流式 token 经过既有无变化快速返回，不触发诊断 epoch / watcher / 扫描。
- 定位调用安全整数参数 `/chat-jump N`，不依赖目标已渲染的 DOM。调用前后复核 scope、绑定代次、聊天、消息身份、准确正文和 swipe；异步变更不关闭新面板或报告旧定位成功。
- 不支持命令时保留面板并显示准确楼号。TT 空结果可能表示未找到 DOM，因此仅提示“已请求定位”，同时给出按楼号查找的回退说明。

## 固定宿主源码证据

核验 [TauriTavern f6126b4 的 chat-jump](https://github.com/Darkatse/TauriTavern/blob/f6126b4fc9243eb3990f2c0bad86e2afcb502f22/src/scripts/slash-commands.js#L3527-L3588)：参数为零基楼号，支持虚拟化历史路径，空返回值不能证明滚动成功。命令执行器默认可吞解析错误，因此适配器显式传入 `handleParserErrors: false` 和 `handleExecutionErrors: false` 以识别不支持的命令。该源码核验不代表用户安装版或手机现场已经验收。

# v1.4.8 自动备份主线程隔离回执

状态：implemented_unverified。2026-10-15，本轮基线为 `51da044ed1c9843502deb2c50dabbb2e1f986e6d`（v1.4.7）。开工时本地工作树干净，远端 `work/daily-memory-mvp-baibai` 同为该提交。本候选尚未发布。

## 问题与定位

用户报告自动备份期间 TT 整个页面滚动间歇停顿，直到备份完成。源码可确认：`CoreBackups.read` 的严格 JSON 解析、整包 JSON 序列化 / TextEncoder、数据摘要与完整领域校验都在页面线程；导出与发布也包含整包运算。轮换时还逐个重新验证 5 / 10 份保留包和待删包。已有 v1.4.3 的线性 DAG / 旧快照路径修复仍保留，但不能消除这些大段同步任务。`async` 函数与 WebCrypto await 并不把前面的 JSON 运算移到后台。

这属于源码定位，未取得用户手机 profiler，不宣称已经量出 TT 卡顿的唯一原因。

## 实现

- 新增内联专用 Worker：自动备份整个 `CoreBackups.save` 流程及同步正文删除前的 `protectCurrentDeletion` 在 Worker 内运行。
- Worker 按明确库名打开同源已有 IndexedDB；缺库或需要升级时中止，不建空库、不迁移。完整 readonly 快照、解析、校验、哈希与生成 Blob 都留在 Worker。
- 主线程只收发库名、Branch 身份、文件键、Blob、简短预览与结果；不克隆整份 Package 到主线程。原生 TT 文件接口仍由主线程代理。
- 继续使用原 `CoreBackups` 算法和保护语义：完整读回验证、保留包校验、归属检查、保护包永久单列、删除前保护与原 CAS 均不省略。
- 共享原 manager 写入队列；Worker 通过异步 guard 查询当前主线程状态，原生 write / remove 调用前在主线程再次立即核对。
- Worker 被禁止 / 创建失败 / 消息异常时不回退为主线程整包运算。启动等待上限 15 秒，单次处理上限 5 分钟；终止 Worker 后仍等待已经发出的原生 IO 结束再释放串行队列。
- 若原生 IO 结果一直不明，展示明确等待状态并继续保留队列占用，避免并发写入 / 删除。终止 JS 不等于取消原生 IO；不能承诺卡死的宿主磁盘调用可被此插件取消。
- 复用项目现有 `?worker&inline` 打包方式，Worker 嵌入 `dist/index.js`，不增加需部署的脚本 URL。

## 范围与不变项

DB3、核心包 v13、文件格式、自动备份调度 / 退避、依赖均不变。不触碰用户数据、设置或宿主安装。手动保存 / 恢复、读取备份列表、手动档案删除面板流程仍沿原实现；本轮不声称所有手动整包操作都已线程隔离。Native Blob 传输本身是否在 TT 适配层产生额外开销，仍需要真实宿主观测。

- `npm test`：69 文件、878 Vitest 测试通过；额外时间关系 810、向量深度 12、记忆回归 53 断言通过，共 875 脚本断言。
- 新增 Worker 边界测试：仅传库身份与 Blob、写入和删除前 guard 竞态、Worker 不可用安全拒绝、启动超时、错误 / 处理超时有原生写入未完成时保留串行队列、无后续删除、缺库与旧版本库不创建 / 不升级。
- 新增异步 guard 为 false 时不把 Promise 当真值通过的反例；保留全部既有备份损坏、读回、轮换和删除保护 / CAS 回归。
- `npx vue-tsc --noEmit`、`npm run build`：通过（构建有既有大 chunk 提示，无构建失败）。
- `node scripts/test-backup-worker-bundle.cjs`：实际构建产物中的内联 Worker 在 Node worker_threads 中启动并发出 ready；缺库请求安全失败，未发原生磁盘 RPC。此项使用 fake IndexedDB，仅验证打包 / 线程入口，不冒充浏览器性能或同源数据库兼容性。

- 真实 TT / Android Worker、同源 IDB / CSP、原生 Blob IO 与滑动平滑度：pending。Node/fake IndexedDB 测试不等于手机验收。

## 有限设备验收

1. 使用合成或用户自行选择的当前档案，启用自动备份后持续滚动；观察整段导出 / 写入 / 读回 / 轮换，无周期性 UI 停顿。
2. 检查新备份已验证、可选择恢复，旧备份按原 5 / 10 份策略轮换，所有删除保护仍保留。
3. 备份期间切聊天 / 隐藏页面，确认后续写入或轮换被 guard 拦住；已有成功文件不冒充失败后删除。
4. Worker 不可用时只显示暂停 / 重试提示，不出现主线程同步 fallback；磁盘异常仍保留旧备份。
5. 正文删除仍先生成当前核心包保护并读回，再沿原 CAS 同步；保护失败保持原档案。

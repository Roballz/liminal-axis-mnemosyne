# v1.4.43 当前核心库核对与旧库禁用

基线 2561b57，分支 work/daily-memory-mvp-baibai，起始工作树干净。状态 implemented_unverified，待真实 TT / 手机核验。用户授权排查继承是否使用迁移前旧库，并提供前端删除或禁用入口；本次采用可逆禁用，不物理删除任何库。

## 排查结果

正常整理路径 core-backup-runtime.reorganizeCore → activateLibrary 在完整核对并通过原库写入屏障后发布新库；它持久化 ACTIVE_KEY、更新当前连接，并关闭原活动连接。启动从 ACTIVE_KEY 打开。bridge.dailyBranchChoices / forkCurrentChat 均调用 activeLibrary，没有逐库搜索或专门回旧库继承的路径；当前核心包只导出指定活动库，保留的旧物理库不并入包体积。

因此“旧库仍保留”不等于“仍在使用”。合成验证中，整理后继承只在新共享库新增子分支，旧库分支与写入标记不变；重新加载模块后仍打开新库并能读到子分支。不能由源码与合成实验推断用户手机此前具体使用了哪个库；新增界面提供现场可见的当前库身份与存储格式。

发现的防护缺口：activeLibrary 之前只缓存一个 Promise，不检查持久化选择器是否被另一个页面修改。现在发现不一致时拒绝继续使用旧连接，要求重载，而不是静默切回旧库。保留原 Promise 身份，兼容归档并发守卫。

## 修改与数据边界

- 档案页增加“核心库管理”：手动检查当前库及共享存储格式，列出同源其他核心库，逐个禁用/解除禁用。当前库无禁用按钮，后端也拒绝禁用当前库或使用过期列表。浏览器无数据库枚举 API 时明确说明，不能枚举的旧库不猜测处理。
- library-policy：禁用名称保存为本机 localStorage 设置；只在原始字符串变化时解析，避免普通事务重复 JSON 解析。格式异常停止，不静默忽略。设置未写入成功不会报告成功。
- db：活动库读取、启用发布前均核对禁用状态；读写事务也核对，旧连接不能绕过禁用继续归档。当前页面的活动连接若与持久化选择不一致，也拒绝写入。启用操作在异步屏障后再次检查，防止等待期间被禁用。
- 解除禁用不切换活动库。禁用不删除数据、不释放空间、不修改摘要、来源、事件或分支历史，不改变备份文件。独立只读访问仍可保留作核验用途；后台任务不进行正常归档/分支继承，整理/恢复仍只写新目标库并由前台校验发布。
- 本机禁用规则不放入故事核心包，不影响另一设备恢复为新库。回退旧插件版本或清除本机设置后，该版本无法执行本次新增禁用规则；不是底层数据库权限系统。
- 面板不在挂载或刷新聊天时扫描，只在点击时查询数据库名称及已有连接格式标志，不打开每个旧库、不读取正文摘要、不统计整库体积。

# v1.4.9 原生编辑确认与摘要弹窗回执

日期：2026-10-16。基线为已发布 v1.4.8 `eb08dac5385cb08697c5d19ec996f38b7b8e2c0f`，分支 `work/daily-memory-mvp-baibai`。本候选先实现和验证，发布须另行确认；状态只到 implemented_unverified。

## 本轮范围

用户报告完整回复后附 API 错误，删除错误尾巴并点击原生编辑框勾号后，摘要审核按钮仍灰、归档页缺少处理项。本轮修复两个已复现的代码缺口：旧生成状态未随终态处理器解除、编辑弹窗早于宿主 UPDATED 完成。用户随后授权同候选调整摘要卡“关联事件”标签与多长名称的布局。

已复现不等于已取得手机现场事件轨迹。没有读取或导入真实聊天，没有调用付费摘要 API，没有修改用户手机或 TT 代码。

## 实现

- `ReplyFinality.edited()` 仅在真实保存意图、准确正文及聊天 / 消息 / swipe 一致时处理。没有 UI END 的恢复路径要求同一 run 的收到回复、匹配楼层的终态 processor、且 processor 不是开始前遗留对象；新替换对象或空 processor 本身不提供证据。
- 实际仍活跃的宿主或已绑定 processor 独立否决接受，即使旧 run 已 marked ended/stopped。保存哈希期间复核意图序列、run、处理器、聊天、消息和 swipe，不接受迟到结果。
- 桥接层为 EDITED / UPDATED 发送配对、无正文的开始 / 完成通知。只有匹配消息、正文、swipe 和聊天代次的 UPDATED 在完成收据处理后才能通知弹窗。
- 弹窗在开始编辑时关闭旧选择，在对应完成通知后合并一次刷新；200ms 只用于合并归档刷新，不是“保存应该完成”的推断。过后处理、关闭、关闭设置、切聊天、新编辑、新生成以及重复 UPDATED 均不能恢复旧弹窗。
- 普通用户消息编辑也走完成通知，仍可触发受影响 AI 摘要的手动审核。既有手改摘要信号保留。
- 摘要卡标签从“关联事件链”改为“关联事件”；关联名称统一使用 11px / 16px，独立标签保持 12px，与右侧图标按完整换行内容垂直居中。保留 60px 操作列与完整名称，不增加截断、测量或 resize 监听；空关联灰色斜体不变。

## 数据与行为边界

- 无 DB / 核心包格式、依赖、持久 schema 或迁移变化；版本升至 1.4.9 并更新构建产物。
- 不自动认可错误或停止回复；用户必须确认当前正文。正文进入档案后，摘要仍按来源变化待手动保留 / 更新，更新才调用模型。
- 不自动通过其他未确认楼层，不新增独立新故事或重新继承操作。
- 编辑时正则 / 宏改变了确认文本、其他编辑入口、非规范物品旁注在保存后改写正文，仍属于原有保守限制，本次没有偷偷扩大接受范围。

## 有限设备验收

1. 在用户自行选择的聊天中，完整回复尾部出现 API 错误后，只删除错误尾巴，再点击原生勾号；正文恢复归档，受影响摘要出现手动保留 / 更新入口。
2. 保存期间如内容渲染较慢，弹窗不得先出现灰色状态。点过后处理或切聊天后，迟到处理不得重新打开旧弹窗。
3. 实际仍在生成的片段、未经明确确认的停止片段不应被自动归档。无须为了验证反复生成或调用模型。
4. 保留仅保存当前来源审核决定，更新才调用摘要 API；旧摘要 / 档案版本继续保留。
5. 卡片含多个长事件名时，完整名称应换行，字号紧凑，左标签与右图标围绕名称块垂直居中；手机窄屏实际观感仍需用户查看。

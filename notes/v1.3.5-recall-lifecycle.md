# 1.3.5 召回超时与状态清理

- 基线：`9f6321f`，分支 `work/daily-memory-mvp-baibai`。
- 状态：implemented_unverified；以下为源码与合成环境验证，手机宿主现场待用户复核。

## 原因与处理

1. 原请求计时器只覆盖 fetch 到达响应头，正文读取在超时边界外。现在 Query/Embedding/Rerank 读完正文才解除计时；取消信号同时中断请求和等待，保持现有每次请求超时、重试次数与退避规则，没有增加更短的全局超时。
2. 原召回布尔锁使重复进入直接返回；清空注入只使结果失效，没有取消请求。现在每轮持有 controller 与 Promise，同轮重复进入等待同一结果，新输入/切聊天取消旧任务，旧任务不能修改新轮次的状态或注入。
3. 原来上下文失效的早退不更新「进行中」，且首次写注入槽位于 finally 保护外。现在初始化、归档同步、请求和注入共用完整错误/清理边界，早退也转为终态。
4. Embedding 空/无效向量与 Rerank 空/无效结果明确报错；一个重排批次失败后取消其他在途批次。保留既有重排失败的向量/BM25 回退规则，并显示降级原因，失败不落召回缓存。
5. 详情显示同步档案、检查/补齐索引、Query 重写、查询向量化、检索候选及重排阶段。手动索引失败不再被吞掉而显示「已是最新」，后台索引失败仍可稍后补齐。

## 索引入口与数据影响

当前聊天 → 设置 → 向量记忆 → 索引维护 → 重建当前聊天向量索引。无需先清空；按当前有效摘要增量对账，缺失/摘要变更才重新 embedding。

档案数据库与检索索引独立。索引使用 Mnemosyne 库名；柏宝库后端可用则使用后端，否则为浏览器 IndexedDB。清空当前聊天索引不删除正文、摘要或事件链档案。本次未运行用户索引重建，未调用付费模型、迁移数据库、修改档案 schema 或清除任何用户数据。

# 日常手动搜索 Demo 封装规划

日期：2026-09-22。状态：用户已授权日常 demo 施工；本轮封装 implemented_unverified，待 Chat review。

## 定位

这是 Stage-B verified 之后的薄产品化封装，复用现有 T-04/T-05 的 B 本机持久库、导入绑定、只读搜索、旧摘要查看和完整包导出。**不新增后端数据库，不建设 A 服务器，不进入 T-06 自动召回/T-07 摘要/T-08 注入。**

目标是让用户从**当前 TT 聊天 + 柏宝书已有摘要**直接初始化第一份 Mnemosyne 本机档案，然后立即进入手动搜索；后续重开/切换聊天时再复用或人工指定已有档案。用户不依赖 native collector、酒馆助手临时脚本、合成演示 namespace 或开发式手填参数。

## 需要做的最小工作

1. **首次初始化**：当还没有 Mnemosyne 档案时，从当前 TT 聊天读取正文，并从柏宝书读取当前可用的已有摘要；先走 T-04 已验收的预览/确认/落盘流程，创建第一份 B 本机持久库。成功后直接进入工作台，不要求用户先知道 namespace。
2. **正式日常入口**：从隔离导入/测试入口拆出稳定的“Mnemosyne 档案”入口。无库时显示“从当前聊天建立档案”；已有库时直接进入/选择档案。导入/修复入口保留，但不让普通搜索先经过测试面板。
3. **后续已有库选择**：只有已经建立过库后才出现复用/切换。优先当前已确认绑定；多聊天/多库时人工指定，不按同文或文件名猜身份。正常用户不需要手填 namespace、UUID 或勾“创建空库”。
4. **记住最近选择**：仅保存非敏感的本地 UI 偏好（例如最近使用的库/分支或自动跟随当前已确认绑定），不得把正式档案状态藏进前端 localStorage。正式正文/摘要仍只在 B 本机数据库。
5. **重开与 owner 生命周期**：页面刷新/TT重开后重新获取唯一 owner/handle，检查库和绑定状态；pending/paused 只提示，不从搜索页自动 recover/confirm/resume。关闭工作台只关闭自身读会话，不误关同步 owner。
6. **模块版本/缓存处理**：正式扩展加载路径要能在更新后加载同一版本的整棵依赖，避免 T-05 现场遇到的旧 ESM 相对依赖缓存。采用简单版本化发布/刷新策略，不依赖临时 loopback 模块树。
7. **日常 UI 收敛**：首页只保留档案选择、当前/历史快照、搜索、旧摘要开关、继续查找、详情和完整备份。调试计数、native按钮、collector和合成 demo 不进入普通入口。
8. **备份/状态提示**：继续复用完整分页恢复包；明确 16 MiB 当前下载上限、pending/paused/历史档案状态、宿主跳转不可用时的档案回退。搜索不产生业务写入。
9. **最小安装/使用说明**：写清安装位置、首次选择现有库、日常打开、重开、备份、停用/回退。临时验收脚本可禁用，不再作为日常步骤。

## 不做

不加向量/BM25、LLM、自动摘要、自动注入、实体系统、A服务器、GC、移动端专项优化、长档案性能调优或新的存储格式。

## 验收建议

用小型合成聊天覆盖：首次无库 → 从当前聊天+旧摘要初始化 → 进入工作台 → 搜正文与旧摘要 → 关闭/重开后复用 → 必要时人工切库 → 历史/当前切换 → 导出。只做一组受影响 Node/UI 回归和一次短 TT 日常入口 smoke；不重跑 T-04/T-05 全量、旧原生演示、1x/5x 或强杀矩阵。

当前主要工程风险不是搜索或存储，而是**库选择/owner生命周期**和**正式扩展更新后的 ESM 缓存一致性**。

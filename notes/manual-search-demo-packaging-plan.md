# 日常手动搜索 Demo 封装规划

日期：2026-09-22。状态：方案已确认，尚未创建正式任务卡或授权施工。

## 定位

这是 Stage-B verified 之后的薄产品化封装，复用现有 T-04/T-05 的 B 本机持久库、导入绑定、只读搜索、旧摘要查看和完整包导出。**不新增后端数据库，不建设 A 服务器，不进入 T-06 自动召回/T-07 摘要/T-08 注入。**

目标是让用户能够把现有 Mnemosyne 档案作为日常手动资料库使用，而不依赖 native collector、酒馆助手临时脚本、合成演示 namespace 或开发式手填参数。

## 需要做的最小工作

1. **正式日常入口**：从隔离导入/测试入口拆出稳定的“Mnemosyne 档案”入口，直接打开手动搜索工作台；保留导入/修复入口，但不让日常搜索先经过测试面板。
2. **既有库发现与选择**：列出可识别的 Mnemosyne 本机库/已绑定档案，优先推荐当前已确认绑定；正常用户不需要手填 namespace、UUID 或勾“创建空库”。未知/多个候选时人工选择，不猜身份。
3. **记住最近选择**：仅保存非敏感的本地 UI 偏好（例如最近使用的库/分支或自动跟随当前已确认绑定），不得把正式档案状态藏进前端 localStorage。正式正文/摘要仍只在 B 本机数据库。
4. **重开与 owner 生命周期**：页面刷新/TT重开后重新获取唯一 owner/handle，检查库和绑定状态；pending/paused 只提示，不从搜索页自动 recover/confirm/resume。关闭工作台只关闭自身读会话，不误关同步 owner。
5. **模块版本/缓存处理**：正式扩展加载路径要能在更新后加载同一版本的整棵依赖，避免 T-05 现场遇到的旧 ESM 相对依赖缓存。采用简单版本化发布/刷新策略，不依赖临时 loopback 模块树。
6. **日常 UI 收敛**：首页只保留档案选择、当前/历史快照、搜索、旧摘要开关、继续查找、详情和完整备份。调试计数、native按钮、collector和合成 demo 不进入普通入口。
7. **备份/状态提示**：继续复用完整分页恢复包；明确 16 MiB 当前下载上限、pending/paused/历史档案状态、宿主跳转不可用时的档案回退。搜索不产生业务写入。
8. **最小安装/使用说明**：写清安装位置、首次选择现有库、日常打开、重开、备份、停用/回退。临时验收脚本可禁用，不再作为日常步骤。

## 不做

不加向量/BM25、LLM、自动摘要、自动注入、实体系统、A服务器、GC、移动端专项优化、长档案性能调优或新的存储格式。

## 验收建议

用现有已验收的小型库即可覆盖：安装/重开 → 自动/人工选库 → 搜正文与旧摘要 → 历史/当前切换 → 导出 → 关闭再开。只做一组受影响 Node/UI 回归和一次短 TT 日常入口 smoke；不重跑 T-04/T-05 全量、旧原生演示、1x/5x 或强杀矩阵。

当前主要工程风险不是搜索或存储，而是**库选择/owner生命周期**和**正式扩展更新后的 ESM 缓存一致性**。

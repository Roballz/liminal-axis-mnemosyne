# 1.3.1 摘要页性能与进展修复

2026-09-25；基线 `work/daily-memory-mvp-baibai` / `131a677`，独立工作树 `work/v1.3.1-ui-performance`。用户五项修复及后续隐藏卡片内部编号请求。状态：implemented_unverified，手机现场体验及最终 review 未验证。

## 原因与实现

- 1.3.0 每个 SummaryTags 实例读取事件目录时，currentEventHints 都执行 hostVersion，序列化完整宿主聊天及总结。折叠总结仍挂载所有下层卡片，使渲染成本随摘要数量和聊天体量相乘。
- 改为页面共享响应式目录；依赖摘要修订、归档修订及宿主观察代次。没关联事件的卡片不读取目录。仅展开时挂载子节点；普通、搜索及选择列表首批40条，“显示更多”继续，全选仍覆盖全部根和批量公开时的有效叶子后代。保存、异步提交及注入的宿主精确校验没有放宽。
- eventPending 原来把 latestProgress 缺失直接判为概要待更新。现只依真实未整理成员、失效依赖和来源受阻判定。旧概要和关联保留，缺短进展单独展示“尚未填写”。
- 事件编辑新增最新进展及对应成员摘要选择，30字校验，程序从来源摘要取时间；新修订沿既有 v7 核心包导出恢复。卡片放在概要下展示；保留未修改字段，可清除已有进展。
- 计划/悬念取消短标题生成及编辑，内容、当前进展、未决事项各50字。旧长内容不批量截写；主模型展示取50字。主模型常驻使用 p/e 短序号，关联回忆和已了结计划也不泄露内部ID；副模型和 Query 目录继续用稳定ID。
- 摘要多选“公开摘要”收集所选根的有效逐楼后代，统一理由可手改；整批身份预检后，一次重算及调度保存/索引。已有在场人物和关联保留；整段导入历史没有逐楼标签，不伪造标签。
- 设置 → 基本设置新增“显示内部编号（调试）”，默认关闭，影响计划/悬念与事件卡片；不影响主模型注入。版本、manifest 和 dist 更新至1.3.1。

源码改动（不计生成文件、文档与版本）：业务实现 +177/-48 行；构建配置 +3/-1 行；测试 +125 行。比初估300–500行实现更小，复用既有编辑、版本和设置机制。

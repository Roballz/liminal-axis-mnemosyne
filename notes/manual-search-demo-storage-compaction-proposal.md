# 日常搜索导入：最小存储粒度修复提案

2026-09-22。状态：proposal，待用户/Chat 确认格式兼容方案；不是新任务卡，不进入 T-06。当前可安装版本为 0.1.2，导入性能仍未解决。

## 已有证据

- 用户手机上 27 条、约 9000 字同步耗时两三分钟；用户确认 0.1.1 已正确显示 L0 数量。0.1.2 已移除气泡，改用宿主魔法棒入口，侧栏布局待用户实机确认。
- 已有同规模合成计量：80315 次 get、31258 次 put、31248 个物理节点，其中目录持久写 23566 次。输入 8927 字符、无摘要/Swipe。见 evals/manual-search-demo/0.1.1-synthetic-cost.json；这是 Node Map IO，不是手机速度测量，本轮未重跑。
- PagedJSON 为对象每个字段/标量建页，用逐键 AVL 插入产生路径副本；目录又登记这些业务页。正文不是主要字节成本来源。小缓存已不足以解决问题。
- 固定 TT 367b0c7 Database.md 的 batchInsert 自动分配 ID，不能等价替换现有按 hash 槽位指定 ID 的 upsert；不靠降低 syncMode 提速。
- paged-recovery 重放旧请求并比较精确 domain 引用。直接全局替换编码算法会破坏旧恢复包，因此需要版本化，而非悄悄改 writer。

## 建议只做这一条路线

1. 保留当前数据库、协调队列、不可变页、碰撞校验、prepare/execute、flush 和单 root 发布流程。新增紧凑记录编码：小记录整体装页，超页正文按 UTF-8 字节预算分块；仍受现有 8192-byte 页与对象预算约束。
2. 只紧凑化可有界物化的记录和请求材料。全局表、可增长的 view 字典、消息顺序/成员索引继续结构化，避免每次复制全库。长正文块保持独立，局部更新不应复制其他正文。
3. 旧 bridge 请求保持原 writer 和原重放结果。新请求使用明确的编码版本（建议独立 bridge-compact-v1 kind），重放按请求版本选择。修改的 json read/field/set/token 流都要理解新记录；只读操作不得为了字段访问持久写新页。
4. 新页格式首次成为可见 checkpoint 时，把 root 格式升级为明确的 v2；旧读者在根上拒绝，不能读一半才报错。升级与正常 root 发布同一边界，不能在纯校验失败前修改旧 root。导出 metadata、恢复 staging/激活及 diagnostics 使用实际格式。
5. 新版本能读 v1 和 v2；v1 的 pending 请求先按原版本恢复，不能换 ID/换编码重试。默认不批量重编码旧材料、不删历史、不 GC：本次修复降低后续新增写入成本，既有膨胀不会自动消失。
6. 完整备份保留新旧混合材料和操作版本；恢复目标仍要求空库。升级前保留完整 v1 包。首次 v2 发布后不能直接退回 0.1.2 写同一库；回退仅用兼容读者，或在另一个空目标恢复升级前备份，并明确该备份不含升级后的操作。

这涉及持久编码兼容边界；不把它描述为普通 UI 返修或不影响回退的小优化。尚未实现上述方案，也未升级用户库。

## 修改范围与预算

- packages/storage/paged-json.mjs：紧凑编码读写与路径/分块处理。
- packages/storage/paged-domain.mjs：记录写入策略、字段访问和逻辑 token 一致性。
- packages/storage/paged-coordinator.mjs、paged-recovery.mjs：请求版本、根格式、导出恢复兼容。
- bridge 发起请求的最小适配、demo 发布版本与说明；不改变宿主读取、摘要白名单、来源绑定和搜索可见性。
- 预计实现新增/修改 250～400 行，必要测试 100～160 行，文档约 50～80 行。若局部字段访问必须重造整套 JSON 层或明显超预算，先重新收敛，不扩成通用新数据库。

## 有限验证与交付顺序

实现期间不逐部件反复测试，最终候选集中执行：

1. 固定旧 writer 生成的小型 v1 包，在新 reader 中恢复并核对旧请求精确重放；包含一个旧 pending 请求续传。
2. 小型新旧混合库：正文、L0、一次修改/Swipe、重开搜索、完整导出恢复；确认编码版本未知时拒绝，纯失败不升级 root。覆盖已有未完成结果保护，不重跑旧强杀矩阵。
3. 同一个 27 条合成 cost-probe 只跑一次最终候选，比较 get/put/节点/字节，不以 Map 耗时冒充手机提速。目标是至少数量级降低底层写入；未达到则不宣称解决，说明残余成本后再收敛。
4. 必要反例和受影响存储/工作台集合各一次；不跑全仓库或旧原生演示。精确命令按最终影响面确定，长日志落文件。
5. 达到最小验证线即更新安装分支，让用户以小档案实际同步、重开、搜索；公布版本与计量，不要求先导入百万字。手机实测之前只标 implemented_unverified，不承诺百万/千万字容量。

## 回审点

需要确认的是第 3～6 项持久格式及回退边界，非魔法棒入口。依据 AGENTS.md「需要改已定规则、底层发布协议或权限时带证据和最小方案回审」。用户已授权解决导入慢和实机优先；本提案把涉及旧库的具体兼容选择呈现出来，不能将一般性能授权理解为允许静默升级格式。

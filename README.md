# Mnemosyne 档案 · 日常手动搜索 Demo 0.1.2

需要 TauriTavern 已有的公开 chat/current、stableId 和 B 数据库 API；不是浏览器 SillyTavern 通用存储扩展。只读当前聊天和柏宝书 v1 公共摘要接口；不调用模型、不注入、不自动同步。

## 安装与日常使用

1. 解压 `mnemosyne-manual-search-0.1.2.zip`，把其中 `mnemosyne-manual-search` 文件夹放到 TT 数据目录的 `extensions/third-party/` 下。该文件夹里应直接看到 `manifest.json`、`index.js` 和 `runtime-0.1.2/`，勿套两层同名目录。
2. 在 TT 扩展管理中启用“Mnemosyne 档案 · 手动搜索”，刷新 TT 页面。此前 T04/T05 临时助手脚本可停用，不需要启动 collector。
3. 打开需要归档的聊天，在输入区魔法棒菜单点“Mnemosyne 档案”，输入自定义库名，点“建立库”。核对正文/摘要数量，再点“确认写入本机库”。没有柏宝书时可只建正文库。
4. 搜索默认查当前已同步正文及已有摘要。下拉可选“当前正文 + Swipe”，结果明确标记候选。只含最近同步读到的 swipes 数组，不等于全部历史，也不含已删除消息的历史候选。每条消息至多一个结果；当前正文已命中时优先显示正文，否则候选详情列出全部匹配的候选槽位。
5. 后续点“同步”→核对→确认，单向更新所选库；必须回到其绑定的原聊天，不会把另一聊天写入此库。聊天变化只清除失效结果，不自动写库。重开面板优先选择当前聊天的已确认绑定。
6. 库下拉可切换其他聊天档案；“更多档案”分批列出其余库。入口位于魔法棒菜单，浮窗标题栏可拖动；右下角金色角标可拖动调节大小，聚焦后方向键也能调节。◐切换浅色/深色；×收起。

## 内容和备份

不同命名“库”是同一个项目 B 物理库中的独立绑定档案，故事/分支隔离；独立命名空间为 `mnemo-t03-paged-manual-demo-v1`，不猜测或复用旧实验库。库名和绑定在数据库内，localStorage 只保存主题偏好。

同步后默认查询最新正文和本次仍存在的摘要。旧摘要完整生成来源仍标记“未证明”，未改动摘要的原始归档作用域不伪造更新。旧正文、旧摘要与恢复材料保留，不物理清理，不提供历史/分支管理界面。

“完整备份”导出整个物理库（所有命名档案），含旧正文、候选和恢复材料，上限16 MiB。备份可能包含私人聊天，请妥善保存，不上传源码仓库。沿用分页恢复包格式；新 v1 demoArchive 桥接元数据须由本版本或兼容新版本恢复工具读取，旧版 T05 不认识此记录。面板暂不提供文件恢复向导。

## 中断、边界与回退

- 写入失败/待完成操作：先点“恢复待完成操作”，恢复原已准备操作，再保持原聊天内容重新预览同步。保留已提交批次。原固定输入已变而无法继续时，保留备份人工处理，不自动另建库逃避错误。
- 重命名/复制/分支等身份或位置变化不猜测归属。暂不支持人工重绑、合并、库删除/改名。
- 单次沿用32 MiB输入限制，目录清单最多512条已有摘要；单对象显示262 KiB，每批搜索受读量/文本/时间预算限制。超限报告未检查完，不假称无结果；不优化超大档案。
- 收起窗口只取消读会话，不抢关正在同步的 owner。停用扩展后刷新页面，入口和事件随页面销毁，不删本机库。调试时可 `await window.__mnemosyneDaily.dispose()` 卸载本页入口并排空关闭 owner。回退前备份，不手工删库，不让旧版工具改写 demo 库。
- 更新时递增 manifest、entry 和 runtime 目录版本，刷新 TT，保证整棵 ESM 依赖一起更新；不要只换根脚本或加随机 query。

## 构建与有限验收

`node apps/manual-search/build.mjs` 生成 `dist/mnemosyne-manual-search/`，只复制入口可达依赖，无测试、collector 和原生脚本，附 SHA256 清单。ZIP 包含整个该目录。

Node/fake 不等于原生 TT 验证。首次安装用小型合成聊天手动检查：建库→正文/摘要搜索→Swipe 范围→追加后同步→收起重开→完整备份。不重跑 T04/T05 演示或强杀矩阵。状态 `implemented_unverified`，供 Chat review。
